## 2. 卡住的问题（接手要解决的）

### 问题 A：断口和直角弯分不开 ❗**最核心**

**现象**：盲走区（赛道底部长 1.68 m 的断线）会让车"转 105°"而不是直行，所以走不了盲走。

**原因**：直角弯的实现方式是"**灰度丢线 → 转 105°**"。而断口也是"灰度丢线"。两者在灰度上没区别。

**实测数据（关键，别重复测）**：

| 位置 | 丢线前 `err` | 补线斜率 `slope` | 平均 \|err\| `mabs` |
|---|---|---|---|
| 直角弯 | **50 ~ 250（随机跳）** | **0** | 0.5 ~ 2.5 |
| 断口 | ≈ 0 ~ 50 | 0 | ≈ 0 |

**为什么分不开**：直角弯的线是"一瞬间扫出视野"的，最后几个采样可能是任意值。
**同一个直角弯，连测多次 `err` 在 50~250 之间跳** —— 任何基于 `err` 幅值的阈值都会时而对、时而错。

**已经试过、都不行的方法（不要重复）**：

| 方法 | 结果 |
|---|---|
| `err_lv >= 2.8` 判弯道 | 实测只有 1.5，永不触发 |
| `err_lv >= 1.2` | 实测 0.5~2.5 随机跳，时而误判 |
| 补线斜率 `slope >= 0.05` | 实测恒为 0（线是平白消失的，没有扫出过程） |
| 平均 \|err\| `mabs < 0.35` 判断口 | 与弯道有重叠 |
| 视觉说"没线" → 直行 | 视觉没调通，见问题 C |
| 丢线后不做判断、让补线自己转 | 直角弯 `slope=0` → 车不转 → 直角弯过不去（已回退） |

**可能的方向（供参考）**：

1. **把 K230 调通**，用它判断前方有没有线（最正规，但要视觉能力）
2. **用赛道进度**：断口在赛道固定位置，用里程/上次元素之后的距离判断（脆弱但简单）
3. **手动开关**：进断口前司机按一下（或拨一个开关），车直行 1.9 m 后恢复循迹
4. **加第二排传感器**（硬件方案）

### 问题 B：六边形环岛切不进去

**入口判据**（`ctrl_fsm.c`）：

```c
if (线有效 && count >= 4 &&
    ((left_edge == 0 && right_edge < 6) || (right_edge == 7 && left_edge > 1)))
    ↓ 持续 150 ms
→ EL_LOOP_IN
```

**还缺数据**：需要在入口正前方停下，发 `d`（连续显示 8 路），看图案怎么变。
**怀疑**：① `count >= 4` 太严（六边形分叉是 60°，可能只有 3 路连黑）；② 这个入口先被判成了直角弯（`EL_TURN90`），所以永远进不了环岛。

**怎么查**：跑一次，看 `[el]` 序列 —— `2→6→7→8` 是正常环岛，`2→12→13` 就是被当成直角弯了。

### 问题 C：K230 视觉

**通信链路是通的**（这部分可以放心）：

```
[cli] visv valid=1 kind=LINE x=.. tn=.. tf=.. xf=.. age=8ms
[cli] vis frames=7044 drop=0 crc_err=0
```

- 协议：`0xAA 0x55 | 0x10 | LEN | PAYLOAD(12) | CRC8`
- 帧内容：`valid, x, y, frame_id, label, angle, flags, quality`
- K230 接 STM32 的 **USART6（PC6/PC7）**，115200
- 实测 30 Hz、`age` 4~40 ms、**CRC 零错**

**没通的是"识别逻辑"**：试了三套都不可靠：

| 方案 | 问题 |
|---|---|
| 双带线性回归 + 倾角判据 | 静态下能分开（直道 −6°、右直角 +72°、左直角 −63°），但**实车抖动时乱跳** |
| 黑块宽度判"横杆" | 板子上跑不起来（`find_blobs` 兼容性问题） |
| **中间竖带数黑像素**（`k230_simple.py`，当前版本） | 只看中间 40% 宽有没有黑，逻辑最简单，**但没验证过断口处 `near` 是否真为 0** |

**接手的人需要做的第一件事**：跑 `fw/vision/k230_simple.py`，在断口处看控制台 `near=` 的值。

```
near=0    → GAP，可以用
near>0    → 摄像头还把断口当"有线"，要调 STRIP_X0/X1 或 MIN_BLACK
```

## 5. 踩过的坑（省得重新踩）

| 坑 | 症状 | 结论 |
|---|---|---|
| 循迹 I2C 太快 | 只有 5 路能用、L1 显示成 L4 | **必须 25 kHz**（`z 20`） |
| 测速量化太粗 | 稳态误差 4~8%、积分"冻结" | 改 20 ms 滑动窗口 |
| `kd` 太大会放大量化台阶 | 弯道猛甩、直道正常 | `kd` 保持 0，除非重做微分 |
| 丢线故障白名单漏了 TURN90 | 转一半电机断电，只转 58° | 白名单要包含所有"允许没线"的状态 |
| 提前退出转弯没设角度门槛 | 旋转中扫到旧线 → 只转 58° | 要求转过 ≥95° 才允许提前结束 |
| 进弯前不刹车 | 内轮要跳变 495 mm/s，跟不上 → 有时准有时甩 | 加 220 ms 刹车相 |
| 环岛入口判据没持续时间 | 直角弯被判成环岛 | 贴边要持续 150 ms |
| 视觉 `find_blobs` | 板子上跑不起来 | 回退到 `get_regression` |
| 相机没对准中线 | `x` 一直是 600~800（应 ≈0） | 物理摆正摄像头，或用相对量 |

## 6. 给接手的人的建议顺序

1. **先跑一次**，确认底盘和循迹正常（`c 550 0 300 300` → `a`）
2. **解决问题 A**（断口）—— 这是能不能跑完整圈的关键。
   最快的路是：把 K230 的 `near` 调成"断口=0、直道>0"，然后用它做丢线时的分流
3. **解决问题 B**（六边形环岛）—— 先采数据（`d` 的图案 + `[el]` 序列）
4. 都通了再谈提速

**时间估计**：A 顺利的话 1 天（如果视觉能用），B 半天。
