# 03 分阶段实现路线与验收标准

版本：v0.1 / 2026-11-15
用法：从上往下推进，**每个阶段的"判据"不满足，绝不进下一阶段**。这是校赛拿分最有效的一条纪律。

---

## 0 路线总览

| 阶段 | 目标 | 关键交付 | 预计工时 |
|---|---|---|---|
| P0 | 硬件自检 | 板子不冒烟，能烧录，串口能打印 | 0.5 天 |
| P1 | 电机开环 | 正反转/调速/STBY 全部正确 | 0.5 天 |
| P2 | 编码器闭环 | 定速巡航 ±2%，左右轮一致 | 1 天 |
| P3 | 循迹 | 低速（0.3 m/s）稳定跑完直道和 90° 弯 | 1–2 天 |
| P4 | IMU 接入 | 串级上线，速度提到 0.8 不掉线 | 2 天 |
| P5 | 蓝牙上位机 | 波形 + 在线改参 | 1 天 |
| P6 | 视觉 | 帧率/延迟/丢帧率达标 | 2 天 |
| P7 | 元素状态机 | 整圈不停车跑完 | 3–5 天 |
| P8 | 提速与鲁棒性 | 目标单圈时间 ±5% 重复性 | 持续 |

> **顺序不能变。** 尤其是 P4 不能跳过 P3——没有低速稳定的循迹，串级只会在错误的误差上放大抖动。

---

## P0 硬件自检

**做什么**
1. 不装核心板，先给 5V 模块输入，调到 5.00 V。
2. 装核心板，测 3.3 V，摸稳压器温度。
3. SWD 能识别、能烧录、能单步。
4. USART1 115200 打印 `hello`（用 `printf` 重定向到 DMA）。

**判据**
- [ ] 三路电源对地无短路，3.3 V 在 3.25–3.35 V。
- [ ] 能烧录，能复位后自动运行。
- [ ] 串口持续打印 1 分钟不掉字。

**注意**：`printf` 一定要重定向到 **DMA 发送**，不要用阻塞版。阻塞的 `printf` 会在你最需要看日志的时候把控制循环拖死。

---

## P1 电机开环

**做什么**
1. `STBY=1`，给固定占空比 20%，看轮子转向。
2. 校准 `MOTOR_L_INVERT` / `MOTOR_R_INVERT`。
3. 加斜坡：占空比每 5 ms 最多变化 N。
4. 测堵转电流（限流电源，别烧 TB6612）。

**判据**
- [ ] 指令正转，车前进（不是原地打转）。
- [ ] 占空比 20/40/60/80% 转速近似线性。
- [ ] 指令 0 时轮子滑行；`STBY=0` 时彻底断电。
- [ ] 急停（按键）响应 < 20 ms，`STBY` 拉低。

**注意**：TB6612 连续 1.2 A 而电机堵转就 1.2 A，**余量为零**。起步必须有斜坡，禁止占空比从 0 直接跳 80%。

---

## P2 编码器闭环

**做什么**
1. 手转一圈，数 `delta` 总和，算出真实 CPR。
2. 用尺子量轮径，填 `CFG_MM_PER_COUNT`。
3. 速度环 PI + 前馈，先单轮后双轮。
4. 标定死区：占空比低于多少不转。

**判据**
- [ ] 手转一圈的计数值与 `PPR×4×减速比` 误差 < 2%。
- [ ] 目标 300 mm/s，实测 294–306 mm/s（±2%）。
- [ ] 左右轮同目标，实测差 < 3%。
- [ ] 阶跃 0→500 mm/s，超调 < 15%，调节时间 < 150 ms。

**注意**：先只调 P，加到临界振荡再退 30%，最后加 I 消除静差。**前馈先给足**（`duty ≈ 7 × v_mm_s`），PI 只负责修正残差，这样抗扰最好。

---

## P3 循迹（低速）

**做什么**
1. 软 I2C 扫到 0x12，读 0x30，打印 8 位。
2. 实测 `TRACK_BLACK_LEVEL`（黑线是 0 还是 1）。
3. 实测传感器间距、离地高度、有效探测宽度。
4. 加权平均误差 + 纯 P 控制，速度 0.3 m/s。
5. 丢线保护：全白 → 保持上次误差 + 降速 300 ms → 停车。

**判据**
- [ ] 直道 2 m 不蛇形（横向偏移 < 10 mm）。
- [ ] 90° 弯能过，不冲出。
- [ ] 抬起车（全白）能在 300 ms 内停住。
- [ ] 车头歪 30° 上赛道，能自动回正。

**注意**：这一步**只用 P**，先别加 D。D 在量化信号上是灾难，等 P4 用 gyro 替代。

---

## P4 IMU 接入（关键一步）

**做什么**
1. 先把 HWT101 波特率改成 **115200**（9600 撑不住 100 Hz）。
2. 解析 0x55 帧，先只取 `yaw` 和 `gyro_z`，校验和不对就丢弃并重新找帧头。
3. 加上角速度内环：`Δv = Kω(ω_ref − gyro_z)`。
4. 直道切"yaw 保持"。
5. 速度提到 0.8 m/s。

**判据**
- [ ] 车静止时 `gyro_z` 噪声 < 1 °/s（峰峰）。
- [ ] 手转 90°，`yaw` 积分误差 < 3°。
- [ ] 直道 2 m 蛇形幅度比 P3 减少 50% 以上。
- [ ] 单轮垫高（模拟打滑）不失控。

**注意**：`gyro_z` 的正负方向必须和"车向右转"一致。**这是最容易搞反的地方**，搞反了就是正反馈，一给速度就原地打转。上电第一件事：手向右转车头，看 `gyro_z` 是不是正。

---

## P5 蓝牙与上位机

**做什么**
1. CRC8 + 帧解析跑通，`REQUEST_TELEMETRY` 能回帧。
2. 上位机画 4 条曲线：`speed_l`、`speed_r`、`yaw`、`line_err`。
3. `SET_PID` 在线改参，改完立刻生效。
4. 参数存 Flash（最后一页）。

**判据**
- [ ] 50 Hz 遥测连续 10 分钟不丢帧、CRC 错误率 < 0.1%。
- [ ] 改参后 1 个控制周期内生效。
- [ ] 断蓝牙 500 ms，车进入失效保护。

**注意**：**没有波形就别调 PID。** 这一步的投入产出比极高，别省。

---

## P6 视觉

**做什么**
1. 帧率、端到端延迟（拍照 → 串口发出）实测。
2. `valid` / `frame_id` / 超时降级全部打通。
3. 先只做"有没有目标"，再做"目标在哪"。

**判据**
- [ ] 帧率 ≥ 25 fps，端到端延迟 < 100 ms。
- [ ] 拔掉 K230，车继续跑（视觉权重归零，不停车）。
- [ ] `frame_id` 连续，能检出丢帧。

**注意**：延迟要用数据量出来，不能猜。方法：屏幕上放一个跳变方块，串口打印收到帧的时间戳，对比视频里的跳变时刻。

---

## P7 元素状态机

**做什么**
1. 先只做 3 个元素：直道、直角、十字。
2. 加里程窗（`arm` 机制）。
3. 加 S 弯。
4. **单独练盲走区**：先只做"丢线 → 停"的失败保护，确认预算生效；再放开成"丢线 → 直走 → 重新锁线"。
5. 加圆形环岛（yaw 累计 330°）。
6. 加六边形环岛（yaw 累计 360°；有边线跟线、无边线用偏置）。
7. 加起停线。
8. 记录每次状态切换的 `tick/里程/yaw/mask`，出问题能回放。

**判据**
- [ ] 连续 10 圈不停车、不出界。
- [ ] 元素识别率 ≥ 95%（记录误判次数）。
- [ ] **盲走区**：连续 10 次通过，出口重新锁线时横向误差 < 10 mm；故意走歪时预算能兜住（停车而不是冲出去）。
- [ ] **六边形环岛**：连续 10 次绕满一圈，不出现"抄近路穿过"或"多绕一圈"。
- [ ] 起停线停车位置重复性 ±15 mm。

**注意**：状态机每次切换都打一条日志（`element, tick, dist, yaw, mask`）。出问题时这三行日志比看视频有用十倍。

> **盲走区和六边形环岛必须单独练，不能和整圈混在一起调。**
> 这两个元素的失败方式是"越界/逆行"，一旦在整圈里反复失败，你连"是哪一段出的问题"都定位不了。

---

## P8 提速与鲁棒性

- 每次只提 0.1 m/s，跑 5 圈不失误再提。
- 换电池、换地面、开/关室内灯都要复测。
- 建一张"环境 × 参数"表，赛前按现场条件选参数集。

---

## 9 调参顺序（记住这个口诀）

```
先内后外：速度环 → 角速度环 → 位置环 → 状态机
先慢后快：0.3 → 0.5 → 0.7 → 0.85（JGB37-520 带载上限约 0.9，别贪 1.2）
先 P 后 I 再前馈：前馈给 70%，P 补 25%，I 补 5%
一次只改一个参数，改完跑 3 次，看重复性
```

**不要做的事：**
- 不要在看不清波形的情况下改 3 个参数。
- 不要用一次成功的数据定参数（要 3 次重复）。
- 不要在电量 < 11 V 时定参数（电压降会让同样的参数表现完全不同）。

## 10 对 `pin_plan.md` 的评审意见

按重要度排序。**前 4 条会直接导致跑不起来，建议先改。**

### 🔴 P0 级（会直接踩坑）

0. **8 路循迹的位序写反了（已对照亚博官方源码确认）。**
   `pin_plan.md` §5.2 写"bit0 = x1，bit1 = x2，…… bit7 = x8"，
   但亚博官方 `EightWayTrack\BSP\Eight_Tracking\app_irtracking.c` 里是：
   ```c
   *x1 = (IRbuf>>7)&0x01;   /* x1 = bit7 */
   *x8 = (IRbuf>>0)&0x01;   /* x8 = bit0 */
   ```
   **两者完全相反。** 如果你的权重表按 bit0 = 最左来算，误差符号会整体镜像 →
   车朝"偏离的反方向"打方向，表现为**一给速度就冲出赛道 / 来回高频振荡**，
   而且看起来特别像"PID 参数不对"，能查很久。
   → 骨架里已加 `CFG_TRACK_ORDER_REVERSE`（`app_config.h`）。
   验证：手拿黑卡从左往右匀速扫过探头，`line_err` 必须**单调**从负到正（或反过来），
   出现非单调就说明位序或权重表配错了。

1. **TIM6 会跟 HAL 时基打架。**
   CubeMX 一旦启用 FreeRTOS，默认想把 TIM6 当 HAL Timebase。而你的表里 TIM6 是 5/10 ms 控制节拍。
   → **显式把 Timebase Source 设成 TIM7**，TIM6 留给控制节拍。两个都是基本定时器，不占引脚。

2. **HWT101 的 9600 波特率撑不住 100 Hz。**
   11 B/帧 × 100 Hz × 10 bit = 11000 bit/s > 9600。实际上限约 87 Hz，而且一旦解析跟不上就会累积延迟。
   → **改成 115200**（维特智能上位机可改，掉电保存）。表里 4.3 和 9 节的 `IMU_BAUD` 一起改。

3. **`TRACK_BLACK_LEVEL` 是 TODO，但没有定义"全黑/全白"语义。**
   8 路模块最危险的输出就是全 0 和全 1，而 pin_plan 里只有"黑线电平"一个宏。
   → 驱动里必须把 `count==0`（丢线）、`count==8`（十字/停车线/全黑）当成独立状态暴露给状态机，不能混在误差计算里。骨架里已按 `track_feat_t` 实现。

4. **OLED 全屏刷新 25 ms，会拖死控制环。**
   → 明确写进架构：OLED 只在最低优先级任务、10 Hz、局部刷新（只刷变化的 2–4 行）。

### 🟡 P1 级（影响性能/稳定）

5. **8 路软 I2C 100 kHz 偏慢**：读一次 0.39 ms，200 Hz 下占 7.8% CPU，还会拖长控制任务。
   → 提到 **400 kHz**（4.7k 上拉 + 短线可以稳），降到 100 µs。

6. **TB6612 带 JGB37-520 是超配使用的，必须实测确认。**

   | 项 | TB6612 | JGB37-520（12V / 30:1） |
   |---|---|---|
   | 连续电流 | **1.2 A** | 额定约 0.3–0.6 A |
   | 峰值 | 3.2 A（几十 ms） | **堵转约 2.5–3 A** |
   | 电压 | VM ≤ 13.5 V | 12 V（3S 满电 12.6 V，余量很小） |

   你 `pin_plan.md` 写"堵转 ≤1.2 A"，这个数**必须实测**（串联电流表，堵住轮子给 100% 占空比，看 1 秒内的峰值）。
   如果是 2.5 A 级：
   - 正常跑没问题（低速小占空比），但**起步、爬坡、原地卡住会超**；
   - 必须：斜坡限幅（`CFG_DUTY_SLEW`）+ 占空比上限（起步前 500 ms 限制到 60%）；
   - 长期方案：换 **DRV8871**（3.6 A）或 TB6643，TB6612 留作备用。
   - **禁止**长时间堵转测试（几秒钟就能把模块烤到热保护）。

7. **缺少 K230 的复位/使能控制。** 视觉模块跑 Linux，死机是常态。
   → 预留 1 个 GPIO（如 `PF0`）控制 K230 的 RESET 或电源 EN，死机时软件可以硬复位。

8. **缺少硬件急停。** 现在只有软件 `STBY`，MCU 挂了就没救。
   → 加一个拨动开关/大按钮，直接拉低 `STBY`（与 GPIO 通过二极管或跳线共存）。

### 🟢 P2 级（建议，不阻塞）

9. **编码器 RC 滤波 100Ω + 10nF → τ=1 µs**，边沿被拉宽到约 2.2 µs。10 kcount/s 下够用，但建议改 **1 nF** 留余量，或把电阻降到 33Ω。

10. **遥测帧里 `target_x/y` 用 int8（-100~100）**，把 K230 的 ±1000 精度砍到 1/10。
    → 建议改 int16（帧长 +2，LEN 19），调视觉时精度很重要。

11. **建议增加 VM 电流采样**（INA181 之类），用于堵转/碰撞检测和"电池健康"曲线。可选。

12. **软 I2C 必须配置成开漏**（`GPIO_MODE_OUTPUT_OD`），绝不能推挽——5V 上拉会经引脚灌电流。pin_plan 已写"开漏"，但 checklist 里建议再加一条"上电初始为高（释放）"的实测项。

---

## 11 一句话总结

> **先把 P0–P3 做扎实（3 天），这套车的下限就锁死了；P4 的串级决定上限；P7 的状态机决定能不能完赛；K230 只决定加分项。**
> 别在方案阶段纠结 F4 够不够快——它够，问题从来不在那儿。
