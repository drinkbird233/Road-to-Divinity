## 1. 有长期价值的成果（这些是真的做成了）

### 1.1 速度环（数据可复现）

| 目标速度 | 稳态 | 误差 | 波动 | 超调 |
|---|---|---|---|---|
| 100 mm/s | 99.5 | 0.5% | ±3 | 5.0% |
| 300 mm/s | 299.7 | **0.1%** | ±3 | **1.7%** |
| 500 mm/s | 499.9 | **0.0%** | ±3 | **1.0%** |

关键改动：
- **测速窗口 5 ms → 20 ms（4 拍滑动窗口）**。5 ms 窗口在 300 mm/s 时只有 ~10 个脉冲，
  1 个 count = 31 mm/s，量化噪声被 P 放大成极限环，表现为"稳态误差 4~8%、积分不涨"。
- **积分分离**（`i_band = 10`）：阶跃时暂停积分，超调从 26% 降到 1.7%。
- **前馈按实测标定**：2685 duty @ 300 mm/s → `CFG_SPEED_FF = 9.0`。

### 1.2 循迹 I2C 必须 25 kHz（容易踩的坑）

| 速度 | 结果 |
|---|---|
| 200 kHz | 丢前 3 位（看起来像"只有 5 路能用""L1 显示成 L4"） |
| 50 kHz | 丢 1 位 |
| **25 kHz** | **正确** |

模块的 I2C 从机是软件模拟的。**`z` 命令不要改成小于 20 µs。**

### 1.3 IMU 的两个真 bug

- **yaw 读的是 pitch**：解析时用了 `s_buf[4..5]`，正确是 `[6..7]`。修复前 yaw 永远不变。
- **LSB 写错**：原来是拍脑袋的 0.01，正确是角度 `0.0054932`、角速度 `0.061035`（WIT 协议推导）。
  这个错会让所有航向相关功能差一倍。

标定结果：**连转 4 次 90°，累计 −357.6°，误差仅 2.4°**。

### 1.4 K230 通信链路（完全打通，可直接复用）

```
帧格式：0xAA 0x55 | 0x10 | LEN | PAYLOAD(12) | CRC8(poly 0x07, init 0)
[0]valid [1:2]x [3:4]y [5:6]frame_id [7]label [8:9]angle [10]flags [11]quality
接线：K230 TX → STM32 PC7 (USART6_RX)，GND 共地，115200 8N1
```

实测：**30 Hz、`age` 4~40 ms、`crc_err` 恒为 0、`drop` 0**。

**没打通的是"识别逻辑"，不是通信。** 下次接手只需在 K230 侧改算法，STM32 侧不用动。

### 1.5 调试工具与文档

- `push.ps1` / `push.cmd`：一键提交推送（本地提交 → checkout-index 导出 → 推送到 GitHub）
- `[el]` 日志：`元素 / err_lv / mabs / vg / cnt / yaw / slope / dist / fault`，
  **状态切换才打印**，一圏十几行，是判断"为什么这样走"的主要依据
- `K` / `vi`：视觉链路体检（帧数、丢帧、CRC 错、颜色标志、帧龄）
- `v`：整车状态；`c`：转向/速度在线改；`l`/`j`：角速度环；`u`：定角转弯标定
- 文档：`08_tuning.md`（调参手册）、`13_plan.md`（分阶段计划）、`14_handoff.md`（交接）

## 2. 没做成的事：六边形环岛入口

### 2.1 已经测到的硬数据（下次不用再测）

用 `d` 命令把车推过入口，实测图案：

```
L4 L5 L6 L7        ← 逐渐变宽（约 5 次采样，500 ms）
L4 L5 L6 L7 L8     ← L8 亮，count=5，贴右端
L4 L5 L7 L8        ← count=4
L4 L5 L8           ← count=3
L4                 ← 突然收窄
L3 L4
```

另一个采样点还出现过 **8 路全黑**（`raw=00`, `count=8`）。

### 2.2 现有判据

`ctrl_fsm.c` 的 `EL_STRAIGHT` 里：

```c
if (line && trk->count >= FSM_LOOP_SIDE_CNT &&          // 要求 ≥4 路
    ((left_edge == 0 && right_edge < 6) ||
     (right_edge == 7 && left_edge > 1))) {             // 贴端
    持续 CFG_LOOP_ARM_MS (150 ms) → EL_LOOP_IN
}
```

### 2.3 为什么没成（三次尝试，三条原因）

| # | 尝试 | 结果 | 原因 |
|---|---|---|---|
| 1 | 调低 `CFG_LOOP_ARM_MS` | 仍不进 | 弯道判定只要 50 ms，`EL_CORNER` 抢先，之后环岛判定不再执行（它只在 `EL_STRAIGHT` 里） |
| 2 | 在 `EL_CORNER` 里也加环岛判定 + 加偏置 | 进得去但**切不进去** | `EL_LOOP_RUN` 里"看得见线就撤偏置"，而那时看到的是**主线**，把车拉回去 |
| 3 | 全黑时判环岛 + `s_expect_loop` 标记 | **把别的功能搞坏了** | 判据写在共享的 `EL_STRAIGHT` 分发里，连带影响直角弯和全黑处理 |

**根本教训：环岛的判定写在了所有元素共用的 `EL_STRAIGHT` 里，改它必然波及别的元素。**

### 2.4 下次的正确做法（建议）

1. **不要在 `EL_STRAIGHT` 里改。** 新建一个独立状态（比如 `EL_LOOP_APPROACH`），
   由"盲走结束"事件进入，里面只做环岛入口判定，失败就回 STRAIGHT。
   这样无论怎么改都不会碰直角弯和全黑。
2. **在副本工程里改**，调通了再合并。别再在能跑的工程上迭代。
3. 判据建议（基于实测数据）：
   ```
   s_expect_loop（盲走结束置位） && 贴右端(L8 黑) && count >= 3
   ```
   直角弯最多 2 路（`raw=FC` = L7 L8），所以 count>=3 是天然分界线。
4. **进入后不要立刻撤偏置**：`EL_LOOP_RUN` 里"看得见线就撤"是错的，
   因为入口处看到的是主线。要转过 ≥60°（车头真正指向环岛）才交回循迹。
