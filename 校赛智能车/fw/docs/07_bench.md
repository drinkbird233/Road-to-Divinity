# 07 台架验证手册（P1–P4）

前提：已经看到 `[car] boot ok, sysclk=168000000`。

**台架 = 车轮离地、车不跑，只验证"每个外设的方向和数值对不对"。**
顺序不能乱：**电机 → 编码器 → 循迹 → IMU**。跳过任何一步，后面调 PID 都会怀疑人生。

---

## 1 台架命令行

固件里内置了一个文本命令行，**USART1（USB-TTL）和 HC06 蓝牙同时可用**，发一条回车执行一条。

> MicroLIB 不支持 `%f`，所以角度用 `x.x` 拼接打印，不是四舍五入错误。

| 命令 | 作用 |
|---|---|
| `h` 或 `?` | 帮助 |
| `m <l> <r>` | **台架模式**：直接给左右占空比，-8399..8399 |
| `x` | 停车，退出台架模式 |
| `e` | 打印左右编码器原始计数 |
| `t` | 打印八路循迹：mask / 有效路数 / 误差 / 是否有效 |
| `i` | 打印 IMU：yaw / gyro |
| `v` | 打印整车状态：模式 / 故障位 / 元素 / 里程 |

`m` 命令会**绕过整个控制环**（不做 PID、不做循迹），直接把占空比送给 TB6612。
这是唯一能"手动掰着看"的入口，用完记得 `x` 退出。

## 2 P1 电机开环

**前置：把车架空，轮到碰不到地面。** 这条是安全底线。

```
m 800 0      → 只有左轮转
m 0 800      → 只有右轮转
m 800 800    → 两轮一起
m -800 -800  → 两轮反向
x            → 立即停
```

**判据**

- [ ] 正占空比时，轮子朝**车头方向**转
- [ ] 800（约 9.5%）就能转起来 —— 死区补偿在起作用
- [ ] `x` 之后立刻停，且 TB6612 的 STBY 变低（模块不发热）
- [ ] 转速随占空比近似线性（试 800 / 2000 / 4000）

**不符合怎么办**

| 现象 | 原因 | 改哪里 |
|---|---|---|
| 轮子反着转 | 电机线接反，或安装方向不同 | `CFG_MOTOR_L_INVERT` / `CFG_MOTOR_R_INVERT` 改成 1 |
| 完全不转 | VM 没电 / STBY 没拉高 / 模块坏 | 先万用表量 VM，再量 STBY |
| 只有一侧转 | TB6612 某一路坏，或 IN 脚虚焊 | 换一路试 |
| 低占空比抖动不转 | 死区补偿不够 | 调大 `CFG_MOTOR_DEADBAND` |
| 一转就热 | 堵转电流超 TB6612 能力 | 见 `docs/03` §10 第 6 条 |

## 3 P2 编码器

连续发 `e`，一边用手匀速推车轮：

```
[cli] enc L=1234 R=1198
[cli] enc L=1301 R=1265
```

**判据**

- [ ] 推车轮时数字单调变化
- [ ] **车轮正好转一圈，计数变化 ≈ 1320**（11 线 × 4 倍频 × 30 减速比）
- [ ] 左右轮同向推动，计数变化方向一致（不一致说明某一侧 A/B 接反）

**不符合怎么办**

| 现象 | 原因 |
|---|---|
| 数字完全不动 | TIM3/TIM4 没进编码器模式；或 A/B 线没接 |
| 一圈不是 1320 | `CFG_ENCODER_PPR` / `CFG_GEAR_RATIO` 估错 → **按实测反推，别信铭牌** |
| 一圈是 660 左右 | 编码器模式退成了 TI1（2 倍频），回 S3 查 |
| 数字乱跳 | 电机线干扰、地没共、缺滤波电容 |

> 算一下：1320 count/圈，65 mm 轮 → 每 count = 0.155 mm。
> 如果实测一圈是 660 或 2640，那就是倍频或减速比错了一档。

## 4 P3 八路循迹

发 `t`，然后**用一张黑卡（或手指）逐个盖住探头**：

```
[cli] mask=08 cnt=1 err=-50 valid=1
[cli] mask=18 cnt=2 err=0 valid=1
[cli] mask=00 cnt=0 err=0 valid=0
[cli] mask=FF cnt=8 err=0 valid=1
```

**判据**

- [ ] 从左往右扫，`mask` 的置位位置**单调移动**，`err` 从负变到正
- [ ] 全白（悬空）时 `cnt=0`、`valid=0`
- [ ] 全黑时 `cnt=8`
- [ ] `err` 单位是"一个传感器间距"，大约 -3.5 ~ +3.5

**不符合怎么办**

| 现象 | 原因 | 改哪里 |
|---|---|---|
| 扫过去 `err` 忽正忽负（不单调） | **位序反了** | `CFG_TRACK_ORDER_REVERSE` 0/1 对调 |
| 盖黑卡时 `cnt` 反而变 0 | 黑白电平反了 | `CFG_TRACK_BLACK_LEVEL` 0/1 对调 |
| 完全没有数据 | I2C 不通 | 先确认 `mask` 是 00 还是没打印；检查 4.7k 上拉、PD3/PD4 开漏 |
| 数据偶尔乱 | 软 I2C 太快 | `CFG_TRACK_I2C_HALF_US` 从 1.2 调到 2.5（约 200 kHz） |

> **这一节最容易出问题，也最值得花时间。** 位序错的表现是"车一给速度就朝偏离方向冲出去"，
> 看起来特别像 PID 参数不对，实际上一个宏就能修。

## 5 P4 HWT101 陀螺仪

发 `i`：

```
[cli] yaw=0.0 gyro=0.0
[cli] yaw=90.3 gyro=-1.2
```

**判据**

- [ ] 静止时 `gyro` 在 ±1.0 之间小幅跳动（不是死 0，也不是乱跳）
- [ ] 手把车头**向右转 90°**，`yaw` 应变为 **-90** 左右（HWT101 逆时针为正）
- [ ] 转回去，`yaw` 回到 0 附近（不累积漂移）
- [ ] 转动过程中 `gyro` 的**符号与 yaw 变化方向一致**

**不符合怎么办**

| 现象 | 原因 |
|---|---|
| 一直是 `yaw=0.0 gyro=0.0` | 模块还是 9600，或 TX/RX 没交叉 |
| 数字乱跳 | 波特率不匹配 |
| 转 90° 显示 900 | `CFG_IMU_ANGLE_LSB` 量纲错（0.01 vs 0.1） |
| 右转时 gyro 为正 | 符号反了 —— **必须修**，否则串级变正反馈，一给速度就原地打转 |

> 陀螺仪符号是**唯一一个"错了会立刻失控"的**。台架上花 30 秒确认，比在赛道上撞墙强。

## 6 全部通过之后

台架四项全绿，才可以进入"整车落地"：

1. 车放地面，**先用 0.3 m/s 慢速跑直线**（P3 阶段），不带任何元素；
2. 直线稳了再加弯道；
3. 速度每档 +100 mm/s，连续 5 次不失误才继续。

**台架阶段不要跑闭环**：`m` 是开环，`mode` 还是 IDLE，循迹和 PID 都没参与。
等 P4 全过，才用 `KEY1` 或蓝牙 `START` 进入 TRACK 模式。

## 7 台架阶段的常见"没有输出"

| 现象 | 先查 |
|---|---|
| 发命令没反应 | 串口助手是否加了"回车"；是否连的 USART1（PA9/PA10）而不是别的口 |
| 有回显但全是乱码 | 波特率不是 115200 |
| `e` 有数但不变 | 编码器 A/B 没接到 TIM 脚上 |
| 一上电电机就抖一下 | STBY 上电顺序；`gpio.c` 里 PE14 初始电平 |
