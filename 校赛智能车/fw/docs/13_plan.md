## 1. 第一个决策：你同学的东西怎么处理

**结论：全部保留。**

理由：

| 类别 | 内容 | 判断 |
|---|---|---|
| A 修 bug | IMU 两个 LSB（0.01 → 0.0055/0.061）、`s_err_at_loss` 取值、航向符号统一 | **必须保留**，都是确定的错 |
| B 加功能 | 直角弯 `EL_TURN90`、找线 `EL_SEEK`、`u`/`B`/`Y` 命令、元素速度可调 | **保留但先不用**，不触发就不影响 |
| C 调参数 | kp 55 / kd 0 / 300·300 / v_turn 120 | 保留 |

**不要回退。** 回退会丢掉 LSB 那个真 bug 的修复 —— 那个错会让 yaw 读数差一倍，是所有航向相关功能的根。

**唯一要做的是：把没验证的功能"关在门外"**，也就是验收阶段不去触发它们（不摆盲走区、不摆环岛），让它们保持沉默。

## 2. 第二个决策：K230 现在装不装

### 机械：**现在就装**

理由：**重量和重心会改变车的动态**。如果先调好车再装 K230，等于白调一次。
装上去之后调一次，比调两次省时间。

装完必须立刻验证：

```
① d          ← 8 路循迹还读得到吗（K230 会不会挡视线/反光）
② 架空跑 r 300 300，看 vL/vR 稳不稳（重心变了，PID 可能要微调）
③ 看车头是否被压得贴地（离地高度变了会影响循迹灵敏度）
```

### 软件：**先不碰**

理由：

| 原因 | 说明 |
|---|---|
| 车还没跑完一圈 | 视觉是"锦上添花"，底盘跑不完，装了也白装 |
| 增加变量 | 视觉一旦接进来，出错时你分不清是循迹、IMU 还是视觉的问题 |
| 比赛策略 | 规则通常允许不用视觉跑完；先保证"能完赛"再追求"快" |

**视觉放到第 9 阶段。** 现在只做一件事：把支架装好、线理顺、**不接信号线**。

### P0 收拾现场（30 分钟）

**目标**：让源码、固件、参数三者一致，后面所有实验都有基准。

| 步骤 | 动作 | 命令/操作 |
|---|---|---|
| 0.1 | 烧录当前源码 | Keil F8（hex 已生成） |
| 0.2 | 确认固件版本 | 发 `B`、`Y`、`u 90`，看是否有反应 |
| 0.3 | 确认参数基线 | 发 `c`，应回 `kp=55.0 kd=0.0 vs=300 vc=300` |
| 0.4 | 确认 8 路循迹 | 发 `d`，手扫一遍，名字要跟着动 |

**验收**：四条全对。

**如果不符**：说明烧的是旧固件，重新 F7→F8。

---

### P1 台架四测（每个 10 秒，共 30 分钟）

**目标**：把"传感器到方向盘"这条数据链路的符号和量纲全部钉死。
**这一阶段不上车，全部架空。**

| # | 测什么 | 怎么做 | 通过标准 |
|---|---|---|---|
| 1.1 | 陀螺仪符号 | `j`，手转车头向右 | 第二列变**正** |
| 1.2 | yaw 符号 | `i`，手转车头向右 | yaw **变小** |
| 1.3 | 定角转弯标度 | 架空，`u 90`，看轮子转多久 | 转完 `i` 的 yaw 变化 ≈ −90°（±5°） |
| 1.4 | 速度环 | 架空，`o` + `r 300 300` | 稳态 300±5，波动 <±10 |

**1.3 的三次重复**：连续 `u 90` 四次，看累计误差。如果每次多转 5°，四次就多 20°，直角弯会撞墙。

**验收**：四项全过。

**失败处理**：
- 1.1 反了 → `CFG_GYRO_INVERT` 改 1，重编译
- 1.3 标度不对 → 改 `CFG_TURN_TOL_DEG` 或 `CFG_TURN_KP`
- 1.4 不过 → 先别往下走，速度环是所有环的地基

---

### P2 基线跑通：直道 + 缓弯（半天）

**目标**：车能连续跑完**没有直角弯、没有盲走、没有环岛**的那段赛道。

| 步骤 | 动作 |
|---|---|
| 2.1 | `c 550 0 300 300` 回到已验证基线 |
| 2.2 | `a` 启动，跑你同学验证过的那段 |
| 2.3 | 记录：能连续跑几圈？在哪个位置丢线？ |

**验收**：连续 3 圈不丢线。

**如果丢线**：在丢线的位置停车，发 `t` 看 `raw`，判断是"线太弯看不清"还是"速度太快冲出去"。

---

### P3 修掉两个代码缺陷（1 小时，要编译）

**目标**：把 ②④ 真正修好，这样后面的提速和直角弯才安全。

> 这一阶段单独做，改完单独验证，不和别的混。

| # | 改什么 | 怎么改 |
|---|---|---|
| 3.1 | 丢线时保持上次误差 100 ms | 加一个 `CFG_E_HOLD_MS`，丢线后沿用最后有效误差，超时才归零 |
| 3.2 | D 项的采样间隔 | D 用**循迹实际更新间隔**（10 ms），不是 5 ms |

**为什么必须先修 3.1**：现在弯里一旦短暂丢线（3 路以上看不见线），转向指令瞬间归零，车会"直着冲出去"——这正是"弯道冲出去"的另一个原因，`kd=0` 只是让另一个原因不发作。

**验收**：改完重跑 P2，必须还是 3 圈不丢线。

**如果 P2 变差**：说明 3.1 的保持时间太长/太短，调 `CFG_E_HOLD_MS`（50~150 ms）。

---

### P4 直角弯（半天）

**目标**：车能自己识别并通过一个直角弯。

| 步骤 | 动作 |
|---|---|
| 4.1 | 把车摆在直角弯**前 30 cm**，`a` 启动 |
| 4.2 | 看它有没有进入 `EL_TURN90`（`v` 看 `el=` 应该是 12） |
| 4.3 | 看转弯角度对不对（`i` 看 yaw 变化） |
| 4.4 | 看转完能不能找回线（`EL_SEEK` → `EL_STRAIGHT`） |

**验收**：连续 3 次过同一个直角弯，不撞、不丢线。

**失败模式**：

| 现象 | 原因 | 改什么 |
|---|---|---|
| 完全没进 EL_TURN90 | 判据太严：没识别成直角 | `CFG_TURN_ARM_ERR` 放宽 |
| 进了但转早了/晚了 | 到位判据 | `CFG_TURN_TOL_DEG` |
| 转了但角度不够 | 标度问题 | 回 P1.3 |
| 转完找不到线 | `EL_SEEK` 的范围/速度 | 看 11 文档 §1 |
| 转完冲出去 | `CFG_V_TURN` 太快 | 120 → 100 |

> ⚠️ 你同学算过：**300 mm/s 过不了这张图上任何一个直角弯**，所以 `CFG_V_TURN=120` 是有依据的，不要为了快把它改大。

---

### P5 盲走区（半天）

**目标**：车能直线穿过 1.68 m 的断线区。

| 步骤 | 动作 |
|---|---|
| 5.1 | `B 1800 200` 设置盲走预算 |
| 5.2 | 把车摆在断口前，`a` 启动 |
| 5.3 | 车应该进入 `EL_BLIND`（`el=` 5），直行，到里程后自动找线 |
| 5.4 | 如果走不直，量出口偏移量 |

**验收**：连续 3 次穿过，出口偏移 < 15 cm（能被循迹拉回）。

**失败模式**：

| 现象 | 原因 | 改什么 |
|---|---|---|
| 没进 EL_BLIND | 丢线判据没触发 | `CFG_TRACK_LOST_STOP_MS`、`CFG_BLIND_MAX_MM` |
| 走了但歪 | 陀螺仪零偏 / 航向保持太弱 | 上电必须静止 3 s；`l -1 <yaw_kp>` 加大 |
| 提前结束 | 预算太小 | `B` 加大 |
| 撞墙才找线 | 预算太大 | `B` 减小 |

> 分档测：先 `B 300`，再 900，再 1500，再 1830。**不要一次跳到 1830。**

---

### P6 环岛（两个，各半天）

**目标**：圆形环岛和六边形环岛各能绕出去。

**这是最大的空白**——代码有（`EL_LOOP_IN/RUN/OUT`），但从没上过车。

| 步骤 | 动作 |
|---|---|
| 6.1 | 先把车摆在**圆形环岛入口**，`a` |
| 6.2 | 看它进没进 `EL_LOOP_IN`（`el=` 6） |
| 6.3 | 看绕行时 `s_yaw_acc` 累计到 330° 时能不能退出去 |
| 6.4 | 六边形同理，360° |

**验收**：每个环岛连续 3 次绕出，不原地转圈、不提前退出。

**失败模式**：

| 现象 | 原因 |
|---|---|
| 不进环岛，直接直行 | 入口判据没触发（看 02 文档的入口特征） |
| 进去了绕不出来 | `s_yaw_acc` 判据、`CFG_ISLAND_DEG` |
| 绕一半提前退出 | 出口判据太松 |
| 在环里丢线停车 | 环岛速度太快 |

---

### P7 S 弯（半天）

**目标**：S 弯能连续过。

**验收**：连续 3 次不切内线、不冲出去。

---

### P8 整圈（一天）

**目标**：把所有元素串起来跑完整一圈。

**这一阶段的坑不在控制，在"元素之间的衔接"**——比如直角弯转完出来马上接环岛入口，两个判据可能互相干扰。

**验收**：连续 3 圈完整。

---

### P9 提速（按需）

**目标**：在整圈稳的基础上逐步加快。

**顺序**（一次只提一档）：

```
直道 300 → 400 → 500 → 600 → 800
弯道 = 直道的 60~70%
```

每提一档跑 3 圈，稳了再提。

> 提速的天花板不在电机，在**延迟**（你同学算过约 90 ms）和**传感器宽度**。
> 300→800 是 2.7 倍，通常需要同时缩小延迟（提速循迹读取率、减小 LPF）。

---

### P10 K230 视觉（可选，最后）

**前提**：P8 完成（整圈能跑）。

**这时候视觉才有意义**：用来做循迹做不到的事，比如提前识别环岛、识别停车线。

**不做的理由**：比赛规则通常允许纯循迹完赛。视觉是加分项，不是必需项。

## 4. 参数唯一真源

**任何时候车跑乱了，照这个回到已知状态：**

```

```

| 参数 | 值 | 说明 |
|---|---|---|
| `kp` | 55 | 你同学实测最稳 |
| `kd` | 0 | 关掉（缺陷 ②④ 没修之前不要开） |
| 直道速度 | 300 | |
| 弯道速度 | 300 | 与直道同速，不是错 |

**其他参数默认值**（编译进固件，复位就回来）：

```
CFG_TURN_KP     2.0     CFG_TURN_DEG    90
CFG_V_TURN      120     CFG_BLIND_MAX_MM 600（用 B 命令在线改）
CFG_IMU_ANGLE_LSB  0.0054932   ← 已修正
```

## 5. 三条纪律

1. **一次只改一个变量。** 改了两个数结果变好，你不知道是哪个起了作用。
2. **一次只验证一个元素。** 把车摆在元素前面，单独过。
3. **每个阶段记录参数。** 记在 `docs/10_params_log.md`，跑好了就记一行。
