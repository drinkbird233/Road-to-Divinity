# 任务书：让"盲走模式"稳定触发

> 交给接手人。本文自包含，不需要读之前的对话。
> 代码：`fw/`（Keil MDK，STM32F407，双轮差速 + 8 路灰度 + 陀螺仪）
> 相关文件：`fw/app/app_config.h`、`fw/ctrl/ctrl_fsm.c`、`fw/app/app_main.c`

---

## 1. 任务一句话

**在这台车跑完赛道上的直角弯序列后，于"该盲走"的那一刻稳定切进 `EL_BLIND`，
既不能早（会在还有线的地方直冲），也不能晚（会错过 1.5 m 断口）。**

---

## 2. 背景：为什么需要盲走

赛道布局（顺时针跑）：

```
起点 → 直角弯 ×7 → 【1.5 m 断口，地上没有线】→ 六边形环岛 → 终点黑带
                        ↑
                   这一段必须盲走
```

断口长 1.5 m，地上是白板。8 路看不到任何线，只能靠陀螺仪保持航向直行穿过去，
出来后再重新找线进环岛。

**关键结构信息**：进断口之前，是**连续两个右转**，且转完几乎是马上就到断口。

## 3. 现状（代码事实，先看这一节再动手）

### 3.1 判据已经实现了，位置在

`ctrl_fsm.c` 的 `EL_STRAIGHT` → 丢线分支的最前面：

```c
if (s_blind_after_ok && !s_blind_done && seq_ok && (s_turn_cnt >= s_blind_min_cnt)) {
    s_blind_done = 1u;
    s_blind_lock = 1u;                    /* 写死航向：发车方向 + 180° */
    s_o.blind_lock = 1u;
    s_o.yaw_hard   = 1u;
    s_o.kp_scale   = 0.0f;
    s_o.yaw_target = wrap180f(s_start_yaw + CFG_BLIND_YAW_OFFSET);
    enter(EL_BLIND, dist_mm, yaw, tick_ms);
    break;
}
```

配套状态：
- `s_turn_cnt`：每进一次 `EL_TURN90` 加 1（`enter_turn()` 里）
- `s_dir_h1 / s_dir_h2`：最近两次转弯方向（+1 右 / −1 左）
- `s_blind_done`：只触发一次的"门票"
- `s_blind_lock`：这次盲走要写死航向

### 3.2 现在它是**被关闭**的状态

`app_config.h`：

```c
#define CFG_BLIND_MIN_TURNS   200   /* 2026-11-24 实车改：5 → 200 = 关闭 */
```

**这不是失效，是主动关掉的。** 关掉的原因写在注释里：

> 正方形闭环没有断口，跑到第 6 个弯就被判成"该盲走了"，
> 航向被锁死直冲出去，然后彻底丢线 —— 实测连续三趟都栽在这。

也就是说：**判据本身工作正常，问题在触发时机和验证环境不匹配。**

### 3.3 现场可以临时改回来

```
C                    → 查看 turns=x/200 req_dir=1 seq=[a,b] blind_used=0
C 6 1                → 至少 6 个弯 + 最后两次都是右转
C 0                  → 计数清零
```

## 4. 需求：三重同意（缺一不可）

用户明确要求：

> 根据里程数，根据连续两个右转，加转弯次数大于 6，来判断下一次断线是盲走。

翻译成条件：

| # | 条件 | 现状 | 待办 |
|---|---|---|---|
| ① | **转弯次数 > 6**（即 ≥7） | 宏可调，数值待定 | 确认阈值 |
| ② | **最近两次转弯都是右转** | 已实现（`s_dir_h1/h2`） | 验证正确性 |
| ③ | **里程落在窗口内** | **未实现** | 新增 |
| ④ | 只触发一次 | 已实现（`s_blind_done`） | — |
| ⑤ | 触发后写死航向 = 发车方向 + 180° | 已实现 | 验证偏移量 |

### 关于 ① 的阈值，有个矛盾必须先想清楚

| 取值 | 优点 | 缺点 |
|---|---|---|
| **≥5** | 漏认一两个弯也能触发 | 可能提前触发（在还有线的地方直冲） |
| **≥7** | 不会提前 | 漏认一个弯就永远不触发（车冲过断口） |

用户要求 ≥7（"大于 6"），取严格值。**但必须知道代价**：只要漏认一个弯，
这次就彻底失效。所以要做第 ⑤ 条：**失效时要有兜底**（见 §6.3）。

### 关于 ③ 里程窗口

现有代码里没有这个条件。建议实现方式与"断口里程窗"（`s_gap_d0/d1`）同一风格：

```c
int32_t run = dist_mm - s_d_run0;      /* s_d_run0 = 发车原点，EL_START 时记录 */
if (run >= CFG_BLIND_RUN_MIN && run <= CFG_BLIND_RUN_MAX) { /* 允许 */ }
```

**窗口必须实测标定，不能猜。** 标定方法见 §5。

## 5. 里程窗口怎么标定（这是本次任务的第一步）

**不要用正方形闭环标定**，原因见 §7.1。必须用真实赛道，或者至少"7 个弯 + 断口"的复刻段。

步骤：

1. 把 `CFG_BLIND_MIN_TURNS` 改回 `200`（保持关闭），避免标定过程中被误触发。
2. 跑一圈，记下这些日志：

   ```
   [turn] #7/200 seq=[1,1]     ← 第 7 个弯（两连右）时的状态
   [el] 5  ... dist=xxxx       ← 如果不小心进了盲走，这是入口里程
   [el] 2  ... dist=yyyy       ← 断口前的最后一次直道
   ```

3. 取"第 7 个弯结束"到"断口开始"之间的里程，作为窗口：

   ```
   CFG_BLIND_RUN_MIN = (第 7 个弯结束里程) - 100
   CFG_BLIND_RUN_MAX = (断口结束里程) + 200
   ```

   留 100~200 mm 余量，覆盖打滑造成的 6% 里程误差（实测手推 7235 处，
   电机驱动下要到 7692 才到，误差约 450 mm 累积）。

```c
/* app_config.h */
#define CFG_BLIND_MIN_TURNS   7      /* 用户要求"大于 6" */
#define CFG_BLIND_REQ_DIR     1      /* +1 = 右转 */

/* 新增里程窗口 */
#define CFG_BLIND_RUN_MIN     7000   /* [待标定] 相对发车原点 */
#define CFG_BLIND_RUN_MAX     9000   /* [待标定] */
```

### 6.2 加里程条件（必做）

在 `ctrl_fsm.c` 丢线分支的盲走判断里加：

```c
int32_t run = dist_mm - s_d_run0;

if ((s_blind_min_cnt >= 0.5f) && !s_blind_done && seq_ok &&
    ((float)s_turn_cnt >= s_blind_min_cnt) &&
    (run >= CFG_BLIND_RUN_MIN) && (run <= CFG_BLIND_RUN_MAX)) {
    /* 触发 */
}
```

**注意**：`CFG_BLIND_RUN_MIN/MAX` 都为 0 时应该视为"不检查里程"（保持向后兼容），
否则会把原来能跑的场景全部关掉。

### 6.3 失效兜底（强烈建议）

按 §4 的分析，`≥7` 的严格判据一旦漏认就全废。建议加一条**独立于计数**的兜底：

```c
/* 兜底：即使计数没到，只要里程已经进入"断口窗口"且线真的丢了，
 * 就直接进盲走。依据是断口位置在赛道上固定。
 * 这条不依赖 s_turn_cnt，所以漏认弯也不影响。 */
if (!s_blind_done && (run >= CFG_BLIND_RUN_MIN) && (run <= CFG_BLIND_RUN_MAX)) {
    s_blind_done = 1u;
    s_blind_lock = 1u;
    /* ... 同样的写死航向逻辑 ... */
}
```

这条是"保险"，主判据仍以三重同意为准。两条谁先满足都行。

### 6.4 验证航向偏移（必做）

盲走时航向被写死为 `发车方向 + CFG_BLIND_YAW_OFFSET`（默认 180°）。

必须实测确认这个 180 是对的：跑完 7 个弯后，车头方向与发车方向真的相反吗？

- 如果盲走走出来偏左/偏右，改 `CFG_BLIND_YAW_OFFSET`（178 / 182 这样微调）
- 如果偏得很多（>15°），说明发车摆位或赛道结构不同，要重新量

## 7. 已知陷阱（已经踩过的坑）

### 7.1 正方形闭环**不能**验证盲走

正方形是闭环，跑两圈就有 8 个弯，`s_turn_cnt` 会累积到 6、7……
于是判据在**第 2 圈的某个直角弯**触发，但那里没有断口，
车被锁死航向直冲出去 → 彻底丢线。

**实测连续三趟都栽在这**，所以 `CFG_BLIND_MIN_TURNS` 才被改成 200。

对策：
- 正方形上调试时保持 `200`（关闭）
- 或者每跑完一圈发一次 `C 0` 清零计数

### 7.2 "提前入弯"会让计数虚高

如果按 `docs/20_moving_turn_plan.md` 实现了"提前入弯"（`|err| ≥ 2.5` 就进 TURN90），
普通弯道也会进 `EL_TURN90`，`s_turn_cnt` 会比实际直角弯多。

后果：**盲走提前触发**。

对策：计数时区分"真直角弯"和"提前入弯"。比如只有 `|err_lv| ≥ 2.8`
丢线进来的才计数，或者给 `enter_turn` 加一个 `counted` 参数。

### 7.3 断口里 1 路假线会让 `line` 变成 1

断口处偶尔有反光/阴影被当成线（`cnt=1`），`line` 变 1，
于是丢线分支进不去，盲走永远不触发。

现有代码的对策是 `gap_ready`（里程窗锁定时，里程没走完不许退出盲走）。
如果新增里程条件，同理要保证"一旦进盲走，就不许因为 1 路假线退出"。

### 7.4 `CRITICAL`：触发后必须"硬保持航向"

`EL_BLIND` 里如果 `kp_scale = 1.0`（允许循迹），断口的假线会把车带偏。
参考现有实现：

```c
if (s_blind_lock) {
    s_o.kp_scale   = 0.0f;      /* 关掉位置环 */
    s_o.yaw_hard   = 1u;        /* 硬保持：忽略 line_ok 门限 */
    s_o.blind_lock = 1u;
    s_o.yaw_target = wrap180f(s_start_yaw + CFG_BLIND_YAW_OFFSET);
}
```

`yaw_hard = 1` 是关键：没有它，航向保持会被 `line_ok && |e| > 1.2` 这条门限跳过。

### 7.5 日志里的 `seq` 曾经显示垃圾值

`[turn] #3/5 seq=[1,1]` 是对的；如果你看到 `seq=[0,536880852]`，
那是 `app_log` 格式串的 `%d` 个数多于参数个数，读了栈上垃圾。
检查 `app_main.c` 里 `[turn]` 那一行的格式串与参数个数是否一致。

## 8. 验证方法

### 8.1 分三步验证，不要一次全改

| 步骤 | 改动 | 验证什么 |
|---|---|---|
| 1 | 只把 `CFG_BLIND_MIN_TURNS` 改回 7，里程条件先不启用 | 计数和方向序列是否正确（看 `[turn] #n/7 seq` 最后是不是 `seq=[1,1]`） |
| 2 | 加里程窗口 | 触发时机是否落在断口起点附近（看 `[el] 5` 的 `dist`） |
| 3 | 验证盲走过程 | 出来时能不能看到线、横向偏差多少 |

### 8.2 每步的通过标准

```
[turn] #1/7 seq=[-1,0]
[turn] #2/7 seq=[1,-1]
...
[turn] #7/7 seq=[1,1]        ← 最后两次都是右转，这才是触发前提
[el] 5  ... dist=xxxx        ← 盲走入口，dist 应在 [RUN_MIN, RUN_MAX] 内
[tr] el=5 raw=00 cnt=0 ...   ← 盲走中，raw 应该一直是 00（地上没线）
[tr] el=6 raw=E3 cnt=3 ...   ← 出盲走进环岛，raw 出现线
```

### 8.3 失败时的判读

| 现象 | 原因 | 查什么 |
|---|---|---|
| 跑完 7 个弯直接冲过断口，没进 `[el] 5` | 计数没到 7 或 `seq` 不是 `[1,1]` | `[turn]` 最后几行的 `#n` 和 `seq` |
| 在第 5、6 个弯就进 `[el] 5` | 计数虚高（见 §7.2） | 是否实现了提前入弯 |
| 进了 `[el] 5` 但车歪着走 | `yaw_hard` 没生效 / 偏移量错 | `[tr]` 里 `yaw` 是否稳定 |
| 进了 `[el] 5` 很快就跳回 `[el] 2` | 断口假线（见 §7.3） | `[tr]` 里 `cnt` 是否偶尔变 1 |

跑一圈完整赛道，满足全部：

| 项 | 标准 |
|---|---|

## 10. 不要做的事

1. **不要用正方形闭环验证盲走触发**——它会累积计数，必然误触发，已栽三趟。
2. **不要只靠灰度判据**（`mabs` / `slope` / `err_lv`）区分断口和直角弯。
   前六轮反复验证过：两者在 8 路上区间重叠，不可分。
3. **不要在盲走里开着循迹**（`kp_scale = 1`）。断口有假线，会把车带偏。
4. **不要把 `CFG_BLIND_REQ_DIR` 设成 0**（不限方向）来"提高触发率"——
   那样任何两连弯都会触发，比漏触发更危险。
5. **不要为了让它在正方形上也能跑而把阈值调小**，那是把一个"赛道专用判据"
   改成"到处都触发"。正方形就是没有断口，不该触发。

### 12.2 任务书里没写、但代码审出来必须修的一条 ★

**方向锁与 `seq_ok` 会静默互斥。**

`docs/20` 那轮新增了转弯方向锁（串口 `D`：+1 右 / −1 左 / 0 自动）。锁打开后，
`s_dir_h1 / s_dir_h2` 被强制成同一个符号，于是：

- 锁成**左转**（`D -1`）而 `CFG_BLIND_REQ_DIR = 1`（右）→ `seq_ok` **恒为 0**；
- 盲走**永远不触发**，日志里没有任何异常，看起来像"计数没到"。

所以判据已经改成：**方向锁打开时，直接拿锁的方向和 `REQ_DIR` 比较**，
而不是比较历史。两者不一致时 `seq_ok = 0`（这是正确的：锁的方向和赛道结构矛盾）。

> 推论：跑真实赛道时，`D` 锁的方向必须与 `CFG_BLIND_REQ_DIR` 一致（通常是右转）。
> 现场最省事的做法是 `D 1` + `REQ_DIR = 1`。

### 12.3 §7.2"计数虚高"已经被间接解决

任务书担心"提前入弯"会让 `s_turn_cnt` 虚高。当前状态：

- `CFG_PRE_TURN_ENABLE = 0`（提前入弯在这条道上 100% 有害，已实测关闭）；
- 新增 `CFG_TURN_COOL_MM = 150`：转完 150 mm 内的再次丢线不计数、不转弯，
  改走 SEEK —— 残余误差造成的"幽灵弯"不会再进 `EL_TURN90`。

也就是说 `s_turn_cnt` 现在只统计"真的转过去的弯"。
**如果以后重新打开提前入弯，§7.2 的计数虚高问题会回来**，届时必须给 `enter_turn`
加 `counted` 参数区分。

| 断口丢线点 | 第 1 趟 **dist=8145**、第 2 趟 **dist=8058**（差 87 mm，来自发车位置差异） |
| 盲走触发 | `[el] 5` at dist=8058，窗口内 ✅ |
| 盲走过程 | 航向 62° → 47°（目标 48°，写死航向 180° 偏移**正确**） |
| 盲走距离 | 8058 → 9551 = **1493 mm**（断口 1.5 m）✅ |
| 出口 | 看到线（`cnt=3, err=2` → 20 mm 偏）→ `[el] 2` 时 err=0 ✅ |

**结论：`CFG_BLIND_YAW_OFFSET=180` 不需要改**（1.5 m 偏 20 mm ≈ 0.8°）。

### 12.6 由实测修正的一条判据结构 ★

任务书 §6.2 写的是"三重同意 + 兜底"，即窗口是**必要条件**。实测后改成"或"：

```
want = (cnt_ok && seq_ok) || (win_on && win_ok)
```

原因：断口丢线点在两次发车之间漂了 87 mm。若取"与"，窗口下界留的余量从 95 mm
缩到 8 mm，再漂一点就整圈失效 —— 而失效的后果是**在断口把车当直角弯转出赛道**。
取"或"的最坏情况是窗口标偏导致提前进盲走，用 `M` 一看就能修，风险小得多。
