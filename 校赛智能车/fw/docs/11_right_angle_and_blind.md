# 11 直角弯（定角转弯）+ 盲走直行

> 2026-11-22。给两个需求做的实现与验证方法：
> **① 直角弯转准 90°，不多不差  ② 盲走区保持直线**
> 台架验证命令是 `u`，状态机新增 `EL_TURN90` / `EL_SEEK` 两个元素。

---

## 0. 先说结论：为什么直角弯必须"按角度转"

8 路探头的横向视野只有 **±35 mm**（权重 ±3.5，一个间距约 10 mm）。
90° 直角弯的线，在车头还没转过去时就已经**横向离开视野**了——不是"打方向不够快"，
是**物理上看不见**。任何靠"加大 kp / 加 kd"的办法都救不了。

所以直角弯必须换一种控制方式：

```
          正常循迹                          直角弯
  8 路误差 → w_ref（PD）        航向误差 → w_ref（角度环）
                    ↘            ↙
                  角速度环 → 差速 → 速度环 → 电机
                  （这一段两条路完全共用）
```

好处是：**你调好的 `l`（rate_kp）、`g`（速度环）在两条路上都生效**，
不需要维护两套参数。

## 1. 状态机怎么走

```
STRAIGHT ──丢线 30ms 且 丢线前|err|<0.8──► BLIND    （断口，保持航向直行）
         ──丢线 30ms 且 |err| 在 0.8~2.8──► CORNER   （还能跟的急弯）
         ──丢线 30ms 且 丢线前|err|≥2.8───► TURN90   （贴边丢线 = 直角弯）
                                              │
                                    转到 yaw±90°（±2° 内保持 50ms）
                                              ▼
                                            SEEK   （低速 ← 找线）
                                              │ 连续 2 拍看到线
                                              ▼
                                          STRAIGHT
```

`CORNER` 里如果也丢线且 |err| 贴边，同样切 `TURN90`（要求连续丢线 ≥30 ms，防抖动误判）。

**判据用哪个 err**：丢线那一刻 `bsp_track` 已经把 `err` 清成 0，
所以不能再读 `trk->err`。代码里单独维护了 `s_err_lv`（最后一次有效误差），
三个分支都用它。这也是原来"急弯一律被当成盲走"的原因（见第 5 节）。

## 2. 参数表（都在 `app_config.h`）

| 宏 | 默认 | 作用 | 怎么调 |
|---|---|---|---|
| `CFG_TURN_KP` | 3.00 | 角度环 P，°/s 每 ° | 过冲明显 → 降到 2.0 |
| `CFG_TURN_DEG` | 90.0 | 转角 | 换赛道改这里 |
| `CFG_TURN_TOL_DEG` | 2.0 | 到位门限 | 要求更准就 1.0，但会更难满足 |
| `CFG_TURN_SETTLE_MS` | 50 | 到位要保持多久 | 抖就加到 80 |
| `CFG_TURN_TIMEOUT_MS` | 1500 | 转不过来就放弃 | 一般不用动 |
| `CFG_TURN_ARM_ERR` | 2.80 | 判直角弯的误差阈值 | 漏判就降到 2.5；误判就升到 3.2 |
| `CFG_V_TURN` | 150 | 转弯时前进速度 | 越小弧线越紧（150 → 半径约 39 mm） |
| `CFG_V_SEEK` | 180 | 转完找线速度 | — |
| `CFG_SEEK_TIMEOUT_MS` | 800 | 找线超时就停车 | — |

`u` / `l` / `c` 改不了这些（编译期宏），但 `l` 的 `rate_kp` 会直接影响转弯质量。

## 3. 台架验证：`u` 命令

**先别上赛道。** 车架空或放空地，手放在 KEY3 上。

```
i                 ← 记下当前 yaw
u 90              ← 以当前朝向为基准右转 90°，到位自动停
（等 1 秒，车自己停）
i                 ← 看 yaw 是否 = 原来 + 90
u -90             ← 反向转回来，看是否回到原点
```

### 判据

| 结果 | 结论 |
|---|---|
| `u 90` 后 yaw 增量 90±2°，且能停稳不来回摆 | ✅ 直接上车 |
| 停下但过冲后回摆几次（幅度 <10°） | 可接受；嫌难看就 `CFG_TURN_KP` 降到 2.0 重编 |
| 一圈一圈停不下来 / 车身剧烈抖 | `CFG_TURN_KP` 太大 或 `l` 的 rate_kp 太大，先各退一档 |
| 转不到 90° 就停（超时） | 打滑或 `CFG_V_TURN` 太小蹭死区；先升到 200 |
| 转的方向反了 | 符号问题：先确认 `j` 里右转为正（08 文档 6.5） |

### 为什么"能收敛到 0 误差"

角度环是纯 P，稳态时 `w_ref = K × dh`，只要 `dh ≠ 0` 就一直有输出往回转，
所以最终一定停在 `|dh| < TOL` 里。**精度取决于两件事，不是控制器**：

1. **陀螺仪读数准不准**（90° 标定，见下）
2. **到位门限** `CFG_TURN_TOL_DEG`

所以"不多不差"这件事，一半在传感器标定上。

### 90° 标定（比调 PID 更重要）

```
i                 ← 车摆正，记 yaw0
（用手慢慢转 90°，用直角器/A4 纸角卡住，转速 <90°/s）
i                 ← 记 yaw1
```

`wrap(yaw1 − yaw0)` 与 90° 的差 >3° 就别指望车能转准——先解决传感器。
再做一次「连续 4 次 90° 转一圈」，回到原点看是否 ±5°，这测的是标度因子和零偏。

## 4. 盲走直行

### 现在是怎么工作的

```
EL_BLIND:
  kp_scale = 0        ← 8 路位置项完全断开
  yaw_hold = 1        ← 只用航向保持：w_ref += 0.8 × (yaw_ref − yaw)
  v_cmd    = CFG_V_BLIND (200)
  距离预算  CFG_BLIND_MAX_MM (600) ← 超了直接停车，这是最后一道保险
  出口      连续 2 拍看到线 → STRAIGHT
```

**关键改动**：进入 `EL_BLIND` 的瞬间，`ctrl_core` 会把 `s_yaw_ref` 重置成当前朝向。
原来的 `s_yaw_ref` 只在跟线居中时以 0.05 的慢系数跟随，盲走时会拿着一个旧值当参考，
车会朝错误方向偏。现在流程是"**从进入盲走区这一秒起，保持这个方向直着走**"。

### 必须实测的一个数

```c
#define CFG_BLIND_MAX_MM    600     /* [TODO] */
```

**拿卷尺量赛道上那个断口的实际长度**，然后设成 `断口长度 + 150~200 mm` 余量。
太小：还没走出去就停车。太大：真冲出去了它还在往前开。

按 200 mm/s 算，600 mm 要走 3 秒。这 3 秒里陀螺仪积分漂移可以忽略
（HWT101 量级是 °/分钟），所以盲走靠角度是靠谱的。

### 进不去的常见原因

| 现象 | 原因 |
|---|---|
| 断口处不减速、直接冲过去 | 丢线前误差不居中（>0.8），被判成 CORNER/TURN90 了 |
| 进盲走后车身往一边偏 | `s_yaw_ref` 没重置（旧固件）或陀螺仪零偏 |
| 一直走到预算用完才停 | 断口后面没线 / 线在横向视野外 → 量一下断口是不是真的那么长 |

## 5. 顺带修掉的一个真 bug

`ctrl_fsm.c` 里原来是：

```c
s_err_at_loss = err;        /* ✗ err 在丢线时已经是 0 */
```

`bsp_track_read()` 在 8 路全白时会把 `f->err` 清成 0，
所以 `absf(s_err_at_loss) < FSM_CENTER_ERR(0.8)` **永远成立** ——
**急弯丢线一律被判成"盲走区"**，进 `EL_BLIND` 后 `kp_scale = 0`，位置环整个断开，
车头回正、直冲出去。

改成用 `s_err_lv`（最后一次有效误差）之后，三个分支才真的能分开。
这条和 09 文档说的"kd 量化尖峰"、"丢线归零"是三个独立的坑，
**任何一个单独存在都足以让弯道过不去**。

## 6. 上车顺序建议

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 | 台架 `u 90` / `u -90` 各 3 次 | 每次都落在 ±2°，不甩 |
| 2 | 90° 标定（手转 + `i`） | 误差 ≤3°，四次一圈 ±5° |
| 3 | 量断口长度，改 `CFG_BLIND_MAX_MM` | — |
| 4 | 赛道单跑直角弯（慢速 vs=200） | `v` 里能看到 `el=12`（TURN90）→ 转完 `el=13` |

`el` 编号：`2`=直道 `3`=弯道 `5`=盲走 `12`=TURN90 `13`=SEEK。

## 8. 有了真实尺寸：直角弯的几何上限（关键结论）

场地 **2.4 m × 2.0 m**，线宽 **16 mm**。

### 8.1 比例尺与换算

用线宽做绝对标尺反推：图上线条画出来约 2 px，`16 / 2 = 8 mm/px`；
再用外框校验：`2400/256 = 9.4`、`2000/192 = 10.4` → **实际约 10 mm/px**（2 px 的笔画量不准，取外框更可信）。

| 量 | 图上一串像素 | 换算 |
|---|---|---|
| 图形外框 | 256 × 192 px | 2.4 × 1.9 m ✓ 与声明一致 |
| **底部缺口** | 168 px | **≈ 1.68 m** ❗ |
| 左上 45° 斜切 | ≈48 px | ≈ 480 mm |
| 线总长 | ≈1270 px | ≈ 12.7 m |

### 8.2 底部那个缺口 = 盲走区（1.68 m，已确认）

> ⚠️ 本文档 00:30 的版本曾判断"这是起点/终点开口，图上没有盲走区" —— **那个判断是错的**。
> 当时没做误差预算就下了结论。经用户确认，它就是盲走区。下面是补做的计算。

**1.68 m 盲走，误差预算：**

航向保持是纯 P：`ω_ref = K × Δyaw`（`CFG_YAW_HOLD_KP = 0.8`）。
角速度环的**前馈精确标定过**（`FF × G = 1.000`），所以 ω 能跟上 ω_ref。
于是 `Δyaw' = -K·Δyaw`，时间常数 `τ = 1/K = 1.25 s`。

横向偏移就是航向误差在横向上的积分：

```
y = v × θ0 / K
```

| 进盲走时的航向误差 θ0 | 横向偏移（v=200, K=0.8） |
|---|---|
| 0.5° | 2.2 mm |
| 1° | 4.4 mm |
| 2° | 8.7 mm |
| 3° | 13 mm |
| 5° | 22 mm |
| 8° | 35 mm ← **8 路视野边缘** |

**结论：进盲走时航向误差只要在 3° 以内，横向只偏 13 mm，远在 ±35 mm 捕获窗口内。
1.68 m 完全可行。** 该有的信心给 HWT101 —— 它够用。

陀螺仪漂移在这个距离上不是主要问题：HWT101 是 °/分钟量级，
8.4 s 内即使按 5 °/min 算也只有 0.7°，折合横向约 10 mm。

**真正的风险是这三条，按权重排序：**

1. **进入时的航向**（占九成权重）：线断的那一刻，车是不是正对着断口
2. **进入时的横向位置**：航向环只保持方向、不修正已有横偏 —— 入口偏 20 mm，出口还是偏 20 mm
3. **出口能否重新捕获线**：落点必须在 ±35 mm 内

对应到代码：第 1 条靠"元素切换时 `s_yaw_ref = 当前 yaw`"保证；
第 2 条无解（没有横向传感器），只能靠进入前跟线跟得正；
第 3 条靠 `FSM_RELOCK_CYCLES` 的 2 拍确认。

### 8.2.1 为什么"距离预算"不敏感

`EL_BLIND` 一看到线就退出（连续 2 拍），所以预算只是"没找到线时的停车保险"。
**可以放心给足**，不用精确：`B 1830`（1680 + 150 余量）即可。
预算给大了不会冲出去，因为线一出现它就退出了。

### 8.3 结论二：**300 mm/s 过不了这张图上任何一个直角弯**

直角弯的圆角半径很小（图上 1~2 个线宽，**约 20~40 mm**）。
沿半径 R 的圆弧走、速度 v，需要的角速度是：

```
ω = v / R
```

| 速度 | R=20 mm | R=30 mm | R=50 mm |
|---|---|---|---|
| 100 mm/s | 286 °/s | 191 °/s | 115 °/s |
| 150 mm/s | 430 °/s | 286 °/s | 172 °/s |
| 200 mm/s | 573 °/s | 382 °/s | 229 °/s |
| **300 mm/s** | **859 °/s** | **573 °/s** | **344 °/s** |

而转向角速度的硬上限是 `CFG_W_MAX = 220 °/s`（执行机构的物理上限也只有 320 °/s，
由 `CFG_DV_MAX = 420` 和轮距 150 mm 决定）。

**所以 300 mm/s 时需要的 344~859 °/s，是上限的 1.6~3.9 倍。**

反过来说，用**跟线**的方式过 R=30 mm 的弯，最高只能跑：

```
v_max = ω_max × R = 3.84 × 0.030 = 0.115 m/s = 115 mm/s
```

**"一加速就冲出去"不是调参问题，是几何问题。** 300 mm/s 在这张图上，
每个直角弯都必须靠**定角转弯**（先把速度降下来转过去），不可能"顺着线抹过去"。

### 8.4 因此改了 `CFG_V_TURN`：150 → 120

转弯时车身走的弧半径就是 `R = v / 3.84`：

| `CFG_V_TURN` | 弧半径 |
|---|---|
| 150 | 39 mm（比弯的圆角大 → 切内道） |
| **120** | **31 mm ✓ 贴合 20~40 mm 的弯** |
| 100 | 26 mm |

### 8.5 两条可选的提速路径

1. **弯前先把速度降下来**（不用编译）：`c 550 0 300 150`。
   `vs=vc=300` 等于直角弯前完全不减速，车会带着 300 mm/s 冲进弯、
   在减速的同时已经偏出去 40 mm 以上，转完可能连 SEEK 都找不到线（8 路只有 ±35 mm）。
2. **抬高角速度上限**（要编译）：`CFG_W_MAX` / `CFG_STEER_KP_MAX` 220 → 300。
   物理上限是 320，所以 300 还有余量。效果是 R=30 mm 的弯最高过弯速度
   从 115 提到 **157 mm/s**，直道仍可 300。**这是性价比最高的一次提速**。

## 9. 盲走区测试步骤（2026-11-22 加 `B` 命令）

### 9.1 为什么先加了个 `B` 命令

盲走预算和速度原来是编译期宏，改一次要走一遍 Keil，而调盲走需要
`600 → 1200 → 1830` 一档一档试。所以做成在线可调（大写字母全空着，
命令分发 `switch (*p)` 不转小写）：

```
B                  ← 查看：blind max=600 mm  v=200 mm/s
B 1830             ← 只改距离预算
B 1830 300         ← 同时改速度
```

### 9.2 分三档测，不要一次跳到 1.68 m

| 档 | 命令 | 看什么 |
|---|---|---|
| 1 | `B 600` | 走 600 mm 就停，量横向偏差。**先证明它走的是直线** |
| 2 | `B 1200` | 偏差不放大 → 继续 |
| 3 | `B 1830` | 跑完整断口，看能不能重新抓到线 |

### 9.3 每档具体怎么做

```
i                  ← 记下 yaw0
B 600              ← 第 1 档
a                  ← 启动
                   ← 车进盲走区：v 里的 el 应该是 5
                   ← 600 mm 后自动停车
i                  ← 记下 yaw1
```

**两个判据，分开看：**

| 判据 | 怎么算 | 不通过说明什么 |
|---|---|---|
| **航向保持** | `wrap(yaw1 − yaw0)` 应 ≈ 0（<2°） | 航向环没起作用 / 参考取错 |
| **横向偏差** | 用尺量车相对断口中线的偏移 | 入口横偏（航向环救不了） |

`j` 也可以在盲走时开：第 1 列（w_ref）应该一直很小（±几 °/s）。
如果它长时间顶在 220，说明在拼命纠一个很大的航向误差 —— 入口就不正。

### 9.4 失败模式对照

| 现象 | 原因 | 处置 |
|---|---|---|
| `el` 不是 5，车直接冲过去 | 丢线前 `\|err\|` > 0.8，被判成 CORNER/TURN90 | 进盲走前先把车摆正；或临时把 `FSM_CENTER_ERR` 放宽 |
| 一进盲走就往一边拐 | `yaw_ref` 没取对（旧固件没有"元素切换重置"） | 确认烧的是最新固件 |
| 走直线但整体偏一边 | 入口横向偏差 | 进入前让车跟线跟正；这个环没有横向反馈，改不了 |
| 600 mm 内就开始画龙 | 航向环 K 太大 + 速度环滞后 | `l -1 60` 把 `yaw_kp` 降到 0.6 |
| 走完 1830 mm 没找到线 | 落点超了 ±35 mm / 断口比量的长 | `B 2100` 再试，并复盘第 1、2 档的偏差趋势 |
| 中途停了（不到 1830） | 预算到了 | `B` 确认数值 |

### 9.5 提速的边界

横向偏移 ∝ v，所以**慢对横向有利**；但时间越长漂移越多。
按 8.2 的表，v 从 200 提到 300 会缩短时间到 5.6 s，
但同样的航向误差横向偏移会 ×1.5。**先在 200 调稳，再考虑提速。**

## 10. 「走偏」先查数据链路，别先怪精度

### 10.1 从传感器到方向盘，中间有四道关

```
HWT101 0x53 帧 → yaw_raw(int16) → ×LSB → wrap180(- zero) → 航向环 → w_ref
                     ↑              ↑        ↑                ↑
                  字节序         换算系数   零点            符号
```

任何一道错，表现出来都是"走偏"或"转不到位"，但修法完全不同。逐个查。

### 10.2 已修正：两个 LSB 都是拍脑袋的 0.01

`app_config.h` 里 `CFG_IMU_ANGLE_LSB` / `CFG_IMU_GYRO_LSB` 原来都写 `0.01`，
注释还标着 `[TODO]`（= 从没量过）。HWT101 是 WIT 标准协议：

| 帧 | 量程 | 正确 LSB | 原来写的 | 倍数误差 |
|---|---|---|---|---|
| 0x53 角度 | ±180° | 180/32768 = **0.0054932** | 0.01 | **放大 1.82 倍** |
| 0x52 角速度 | ±2000°/s | 2000/32768 = **0.061035** | 0.01 | **缩小 6.1 倍** |

后果：

1. **yaw 放大 1.82 倍** → 实际转 90°，车以为转了 164°。
   定角转弯会在转到 49° 时就"到位"收工 —— **直角弯只转一半**。
2. **角速度缩小 6.1 倍** → 角速度环的 `rate_kp×(w_ref − gyro)` 几乎为零，
   等于纯前馈。"接了陀螺仪没效果"就是这么来的。

### 10.3 已修正：航向符号在代码里是矛盾的

| 位置 | 写的公式 | 隐含假设 |
|---|---|---|
| `ctrl_core` 航向保持（原有） | `w += K*(yaw − ref)` | 右转 yaw **变小** |
| `ctrl_fsm` 定角转弯（本轮新写） | `w = K*(target − yaw)` | 右转 yaw **变大** |

**两者必有一错。** 错的那一路是正反馈，症状就是"车朝一边跑飞"。

现在统一成一个来源 `g_yaw_sgn`（`app_config.h` 的 `CFG_YAW_SGN`）：

```
w = sgn × K × (目标 − 当前)
```

右转到底 yaw 变大还是变小，取决于模块约定，**必须实测**。串口 `Y` 可以运行时翻转。

### 10.4 四个台架测试（每个 10 秒，顺序不能乱）

| # | 怎么做 | 通过标准 | 不通过说明 |
|---|---|---|---|
| 1 | 车静置，连发两次 `i`，间隔 10 s | yaw 漂移 < 1° | 零偏没标定（见 10.5） |
| 2 | `i` → 手转 90°（直角器卡住）→ `i` | Δyaw ≈ 90±3 | ≈164 → LSB 还是旧值（本次已改 0.0054932）<br>≈45 → 方向反了，改 0.01098 |
| 3 | 手把车头**【向右】**转，看 yaw 变大还是变小 | 变大 → 符号 +1<br>变小 → 符号 −1 | 与 `CFG_YAW_SGN` 不符就发 `Y` 翻转 |
| 4 | 架空，`u 90` | 转 90° 后**停住** | 一直转到超时（1.5 s）→ 正反馈，符号错 |

**第 3、4 条是一回事的静态版和动态版**，都过不去就先别上赛道。

### 10.5 零偏：上电时必须静止

HWT101 上电后会用静止状态自标定陀螺零偏。**如果上电那一刻车在动/被人碰，
零偏就是错的**，之后 yaw 会稳定地朝一个方向漂 —— 表现为"走直线但慢慢往一边偏"。

处置：断电 → 车放平、别碰 → 上电 → 等 2~3 秒再动。

### 10.6 判定「走偏」到底属于哪一类

| 现象 | 归类 | 修法 |
|---|---|---|
| 进盲走后**越走越弯**，最后甩出去 | 符号反 → 正反馈 | `Y` 翻转 |
| 走直线，但**稳定地朝一边偏**，角度不增长 | 零偏 / 入口横偏 | 静止上电；进入前跟线跟正 |
| 走直线，yaw 读数**自己慢慢涨** | 零偏 | 静止上电；必要时重标定 |
| `u 90` 转的角度**明显不到 90** | LSB 错 | 见 10.2 |
| 角度对、方向对，但**入口就偏了 20 mm** | 入口横偏 | 航向环没有横向反馈，改不了 |

### 10.7 「u 90 每次多转一点」怎么修

**2026-11-22 台架实测：右转 yaw 变小 → `CFG_YAW_SGN = -1` 正确。**
（也就是说 `ctrl_core` 原有的航向保持一直是对的，错的是我新写的定角转弯，已统一。）

剩下的是"停得不准"。三个原因，逐个对症：

| 原因 | 症状 | 本次处置 |
|---|---|---|
| **到位判据只看角度，不看角速度** | 车还在以 200 °/s 冲过目标时 `\|dh\|` 也会短暂小于容差，判据立刻成立 → 停下时已多转几度 | 新增 `CFG_TURN_STOP_DPS = 30`：角速度也要降下来才算到位 |
| **容差 2.0° 太松** | 每次都差 2°，转四次累积 8° | 收紧到 **1.2°** |
| **K=3.0 太猛** | 逼近目标时速度太高，靠 P 刹不住 | 降到 **2.0** |

> 第二条最隐蔽：**单次误差在容差内就等于"合格"，但累积会暴露。**
> 所以验转角精度不能只看一次，必须连转四次看总量 —— 这也是你发现它的方式。

#### 怎么判断是哪种原因（连转四次，每次记 `i`）

```
i           ← 记 y0
u 90  → i   ← 记 y1
u 90  → i   ← 记 y2
u 90  → i   ← 记 y3
u 90  → i   ← 记 y4
```

把 `y1-y0`、`y2-y1`… 列出来：

| 每次增量 | 结论 |
|---|---|
| 91、91、91、91（**固定偏一点**） | 到位容差问题 → 已收紧到 1.2° |
| 90、92、94、96（**递增**） | 标度误差 → LSB 不对（见 10.2） |
| 90、96、90、94（**随机大偏**） | 过冲 → 降 `CFG_TURN_KP` 或加 D 项 |
| 92、88、93、87（**正负乱跳**） | 陀螺仪噪声/振动 → 检查模块固定是否牢 |

#### 还想更准，就加 D 项（可选，要改代码）

现在角度环是纯 P。有陀螺仪不用白不用，加一项角速度阻尼能明显压掉过冲：

```c
/* ctrl_core 的 w_mode 分支里，把
 *   w_ref = clampf(g_yaw_sgn * CFG_TURN_KP * dh_t, ...);
 * 改成（Kd 约 0.3~0.6 s）： */
float yaw_rate = g_yaw_sgn * gy;            /* 与 yaw 同向的角速度 */
w_ref = clampf(g_yaw_sgn * (CFG_TURN_KP * dh_t - CFG_TURN_KD * yaw_rate),
               -CFG_W_MAX, CFG_W_MAX);
```

先在纯 P 下调到能接受，再考虑加 D —— 一次只改一处。
