# 11 直角弯（定角转弯）+ 盲走直行

> 2026-11-22。给两个需求做的实现与验证方法：
> **① 直角弯转准 90°，不多不差  ② 盲走区保持直线**
> 台架验证命令是 `u`，状态机新增 `EL_TURN90` / `EL_SEEK` 两个元素。

---

## 0. 先说结论：为什么直角弯必须"按角度转"

8 路探头的横向视野只有 **±35 mm**（权重 ±3.5，一个间距约 10 mm）。
90° 直角弯的线，在车头还没转过去时就已经**横向离开视野**了——不是"打方向不够快"，
是**物理上看不见**。任何靠"加大 kp / 加 kd"的办法都救不了。

所以直角弯必须换一种控制方式：

```
          正常循迹                          直角弯
  8 路误差 → w_ref（PD）        航向误差 → w_ref（角度环）
                    ↘            ↙
                  角速度环 → 差速 → 速度环 → 电机
                  （这一段两条路完全共用）
```

好处是：**你调好的 `l`（rate_kp）、`g`（速度环）在两条路上都生效**，
不需要维护两套参数。

## 1. 状态机怎么走

```
STRAIGHT ──丢线 30ms 且 丢线前|err|<0.8──► BLIND    （断口，保持航向直行）
         ──丢线 30ms 且 |err| 在 0.8~2.8──► CORNER   （还能跟的急弯）
         ──丢线 30ms 且 丢线前|err|≥2.8───► TURN90   （贴边丢线 = 直角弯）
                                              │
                                    转到 yaw±90°（±2° 内保持 50ms）
                                              ▼
                                            SEEK   （低速 ← 找线）
                                              │ 连续 2 拍看到线
                                              ▼
                                          STRAIGHT
```

`CORNER` 里如果也丢线且 |err| 贴边，同样切 `TURN90`（要求连续丢线 ≥30 ms，防抖动误判）。

**判据用哪个 err**：丢线那一刻 `bsp_track` 已经把 `err` 清成 0，
所以不能再读 `trk->err`。代码里单独维护了 `s_err_lv`（最后一次有效误差），
三个分支都用它。这也是原来"急弯一律被当成盲走"的原因（见第 5 节）。

## 2. 参数表（都在 `app_config.h`）

| 宏 | 默认 | 作用 | 怎么调 |
|---|---|---|---|
| `CFG_TURN_KP` | 3.00 | 角度环 P，°/s 每 ° | 过冲明显 → 降到 2.0 |
| `CFG_TURN_DEG` | 90.0 | 转角 | 换赛道改这里 |
| `CFG_TURN_TOL_DEG` | 2.0 | 到位门限 | 要求更准就 1.0，但会更难满足 |
| `CFG_TURN_SETTLE_MS` | 50 | 到位要保持多久 | 抖就加到 80 |
| `CFG_TURN_TIMEOUT_MS` | 1500 | 转不过来就放弃 | 一般不用动 |

| `CFG_SEEK_TIMEOUT_MS` | 800 | 找线超时就停车 | — |

`u` / `l` / `c` 改不了这些（编译期宏），但 `l` 的 `rate_kp` 会直接影响转弯质量。

## 3. 台架验证：`u` 命令

**先别上赛道。** 车架空或放空地，手放在 KEY3 上。

```
i                 ← 记下当前 yaw
u 90              ← 以当前朝向为基准右转 90°，到位自动停
（等 1 秒，车自己停）
i                 ← 看 yaw 是否 = 原来 + 90
u -90             ← 反向转回来，看是否回到原点
```

### 判据

| 结果 | 结论 |
|---|---|
| `u 90` 后 yaw 增量 90±2°，且能停稳不来回摆 | ✅ 直接上车 |
| 停下但过冲后回摆几次（幅度 <10°） | 可接受；嫌难看就 `CFG_TURN_KP` 降到 2.0 重编 |
| 一圈一圈停不下来 / 车身剧烈抖 | `CFG_TURN_KP` 太大 或 `l` 的 rate_kp 太大，先各退一档 |
| 转不到 90° 就停（超时） | 打滑或 `CFG_V_TURN` 太小蹭死区；先升到 200 |
| 转的方向反了 | 符号问题：先确认 `j` 里右转为正（08 文档 6.5） |

### 为什么"能收敛到 0 误差"

角度环是纯 P，稳态时 `w_ref = K × dh`，只要 `dh ≠ 0` 就一直有输出往回转，
所以最终一定停在 `|dh| < TOL` 里。**精度取决于两件事，不是控制器**：

1. **陀螺仪读数准不准**（90° 标定，见下）
2. **到位门限** `CFG_TURN_TOL_DEG`

所以"不多不差"这件事，一半在传感器标定上。

### 90° 标定（比调 PID 更重要）

```
i                 ← 车摆正，记 yaw0
（用手慢慢转 90°，用直角器/A4 纸角卡住，转速 <90°/s）
i                 ← 记 yaw1
```

`wrap(yaw1 − yaw0)` 与 90° 的差 >3° 就别指望车能转准——先解决传感器。
再做一次「连续 4 次 90° 转一圈」，回到原点看是否 ±5°，这测的是标度因子和零偏。

## 4. 盲走直行

### 现在是怎么工作的

```
EL_BLIND:
  kp_scale = 0        ← 8 路位置项完全断开
  yaw_hold = 1        ← 只用航向保持：w_ref += 0.8 × (yaw_ref − yaw)
  v_cmd    = CFG_V_BLIND (200)
  距离预算  CFG_BLIND_MAX_MM (600) ← 超了直接停车，这是最后一道保险
  出口      连续 2 拍看到线 → STRAIGHT
```

**关键改动**：进入 `EL_BLIND` 的瞬间，`ctrl_core` 会把 `s_yaw_ref` 重置成当前朝向。
原来的 `s_yaw_ref` 只在跟线居中时以 0.05 的慢系数跟随，盲走时会拿着一个旧值当参考，
车会朝错误方向偏。现在流程是"**从进入盲走区这一秒起，保持这个方向直着走**"。

### 必须实测的一个数

```c
#define CFG_BLIND_MAX_MM    600     /* [TODO] */
```

**拿卷尺量赛道上那个断口的实际长度**，然后设成 `断口长度 + 150~200 mm` 余量。
太小：还没走出去就停车。太大：真冲出去了它还在往前开。

按 200 mm/s 算，600 mm 要走 3 秒。这 3 秒里陀螺仪积分漂移可以忽略
（HWT101 量级是 °/分钟），所以盲走靠角度是靠谱的。

### 进不去的常见原因

| 现象 | 原因 |
|---|---|
| 断口处不减速、直接冲过去 | 丢线前误差不居中（>0.8），被判成 CORNER/TURN90 了 |
| 进盲走后车身往一边偏 | `s_yaw_ref` 没重置（旧固件）或陀螺仪零偏 |
| 一直走到预算用完才停 | 断口后面没线 / 线在横向视野外 → 量一下断口是不是真的那么长 |

## 5. 顺带修掉的一个真 bug

`ctrl_fsm.c` 里原来是：

```c
s_err_at_loss = err;        /* ✗ err 在丢线时已经是 0 */
```

`bsp_track_read()` 在 8 路全白时会把 `f->err` 清成 0，
所以 `absf(s_err_at_loss) < FSM_CENTER_ERR(0.8)` **永远成立** ——
**急弯丢线一律被判成"盲走区"**，进 `EL_BLIND` 后 `kp_scale = 0`，位置环整个断开，
车头回正、直冲出去。

改成用 `s_err_lv`（最后一次有效误差）之后，三个分支才真的能分开。
这条和 09 文档说的"kd 量化尖峰"、"丢线归零"是三个独立的坑，
**任何一个单独存在都足以让弯道过不去**。

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 | 台架 `u 90` / `u -90` 各 3 次 | 每次都落在 ±2°，不甩 |

## 8. 有了真实尺寸：直角弯的几何上限（关键结论）

场地 **2.4 m × 2.0 m**，线宽 **16 mm**。

### 8.1 比例尺与换算

用线宽做绝对标尺反推：图上线条画出来约 2 px，`16 / 2 = 8 mm/px`；
再用外框校验：`2400/256 = 9.4`、`2000/192 = 10.4` → **实际约 10 mm/px**（2 px 的笔画量不准，取外框更可信）。

| 量 | 图上一串像素 | 换算 |
|---|---|---|
| 图形外框 | 256 × 192 px | 2.4 × 1.9 m ✓ 与声明一致 |
| **底部缺口** | 168 px | **≈ 1.68 m** ❗ |
| 左上 45° 斜切 | ≈48 px | ≈ 480 mm |
| 线总长 | ≈1270 px | ≈ 12.7 m |

### 8.2 底部那个缺口 = 盲走区（1.68 m，已确认）

> ⚠️ 本文档 00:30 的版本曾判断"这是起点/终点开口，图上没有盲走区" —— **那个判断是错的**。
> 当时没做误差预算就下了结论。经用户确认，它就是盲走区。下面是补做的计算。

**1.68 m 盲走，误差预算：**

航向保持是纯 P：`ω_ref = K × Δyaw`（`CFG_YAW_HOLD_KP = 0.8`）。
角速度环的**前馈精确标定过**（`FF × G = 1.000`），所以 ω 能跟上 ω_ref。
于是 `Δyaw' = -K·Δyaw`，时间常数 `τ = 1/K = 1.25 s`。

横向偏移就是航向误差在横向上的积分：

```
y = v × θ0 / K
```

| 进盲走时的航向误差 θ0 | 横向偏移（v=200, K=0.8） |
|---|---|
| 0.5° | 2.2 mm |
| 1° | 4.4 mm |
| 2° | 8.7 mm |
| 3° | 13 mm |
| 5° | 22 mm |
| 8° | 35 mm ← **8 路视野边缘** |

**结论：进盲走时航向误差只要在 3° 以内，横向只偏 13 mm，远在 ±35 mm 捕获窗口内。
1.68 m 完全可行。** 该有的信心给 HWT101 —— 它够用。

陀螺仪漂移在这个距离上不是主要问题：HWT101 是 °/分钟量级，
8.4 s 内即使按 5 °/min 算也只有 0.7°，折合横向约 10 mm。

**真正的风险是这三条，按权重排序：**

1. **进入时的航向**（占九成权重）：线断的那一刻，车是不是正对着断口
2. **进入时的横向位置**：航向环只保持方向、不修正已有横偏 —— 入口偏 20 mm，出口还是偏 20 mm
3. **出口能否重新捕获线**：落点必须在 ±35 mm 内

对应到代码：第 1 条靠"元素切换时 `s_yaw_ref = 当前 yaw`"保证；
第 2 条无解（没有横向传感器），只能靠进入前跟线跟得正；
第 3 条靠 `FSM_RELOCK_CYCLES` 的 2 拍确认。

### 8.2.1 为什么"距离预算"不敏感

`EL_BLIND` 一看到线就退出（连续 2 拍），所以预算只是"没找到线时的停车保险"。
**可以放心给足**，不用精确：`B 1830`（1680 + 150 余量）即可。
预算给大了不会冲出去，因为线一出现它就退出了。

### 8.3 结论二：**300 mm/s 过不了这张图上任何一个直角弯**

直角弯的圆角半径很小（图上 1~2 个线宽，**约 20~40 mm**）。
沿半径 R 的圆弧走、速度 v，需要的角速度是：

```
ω = v / R
```

| 速度 | R=20 mm | R=30 mm | R=50 mm |
|---|---|---|---|
| 100 mm/s | 286 °/s | 191 °/s | 115 °/s |
| 150 mm/s | 430 °/s | 286 °/s | 172 °/s |
| 200 mm/s | 573 °/s | 382 °/s | 229 °/s |
| **300 mm/s** | **859 °/s** | **573 °/s** | **344 °/s** |

而转向角速度的硬上限是 `CFG_W_MAX = 220 °/s`（执行机构的物理上限也只有 320 °/s，
由 `CFG_DV_MAX = 420` 和轮距 150 mm 决定）。

**所以 300 mm/s 时需要的 344~859 °/s，是上限的 1.6~3.9 倍。**

反过来说，用**跟线**的方式过 R=30 mm 的弯，最高只能跑：

```
v_max = ω_max × R = 3.84 × 0.030 = 0.115 m/s = 115 mm/s
```

**"一加速就冲出去"不是调参问题，是几何问题。** 300 mm/s 在这张图上，
每个直角弯都必须靠**定角转弯**（先把速度降下来转过去），不可能"顺着线抹过去"。

### 8.4 因此改了 `CFG_V_TURN`：150 → 120

转弯时车身走的弧半径就是 `R = v / 3.84`：

| `CFG_V_TURN` | 弧半径 |
|---|---|
| 150 | 39 mm（比弯的圆角大 → 切内道） |
| **120** | **31 mm ✓ 贴合 20~40 mm 的弯** |
| 100 | 26 mm |

### 8.5 两条可选的提速路径

1. **弯前先把速度降下来**（不用编译）：`c 550 0 300 150`。
   `vs=vc=300` 等于直角弯前完全不减速，车会带着 300 mm/s 冲进弯、
   在减速的同时已经偏出去 40 mm 以上，转完可能连 SEEK 都找不到线（8 路只有 ±35 mm）。
2. **抬高角速度上限**（要编译）：`CFG_W_MAX` / `CFG_STEER_KP_MAX` 220 → 300。
   物理上限是 320，所以 300 还有余量。效果是 R=30 mm 的弯最高过弯速度
   从 115 提到 **157 mm/s**，直道仍可 300。**这是性价比最高的一次提速**。

## 9. 盲走区测试步骤（2026-11-22 加 `B` 命令）

### 9.1 为什么先加了个 `B` 命令

盲走预算和速度原来是编译期宏，改一次要走一遍 Keil，而调盲走需要
`600 → 1200 → 1830` 一档一档试。所以做成在线可调（大写字母全空着，
命令分发 `switch (*p)` 不转小写）：

```
B                  ← 查看：blind max=600 mm  v=200 mm/s
B 1830             ← 只改距离预算
B 1830 300         ← 同时改速度
```

### 9.2 分三档测，不要一次跳到 1.68 m

| 档 | 命令 | 看什么 |
|---|---|---|
| 1 | `B 600` | 走 600 mm 就停，量横向偏差。**先证明它走的是直线** |
| 2 | `B 1200` | 偏差不放大 → 继续 |
| 3 | `B 1830` | 跑完整断口，看能不能重新抓到线 |

### 9.3 每档具体怎么做

```
i                  ← 记下 yaw0
B 600              ← 第 1 档
a                  ← 启动
                   ← 车进盲走区：v 里的 el 应该是 5
                   ← 600 mm 后自动停车
i                  ← 记下 yaw1
```

**两个判据，分开看：**

| 判据 | 怎么算 | 不通过说明什么 |
|---|---|---|
| **航向保持** | `wrap(yaw1 − yaw0)` 应 ≈ 0（<2°） | 航向环没起作用 / 参考取错 |
| **横向偏差** | 用尺量车相对断口中线的偏移 | 入口横偏（航向环救不了） |

`j` 也可以在盲走时开：第 1 列（w_ref）应该一直很小（±几 °/s）。
如果它长时间顶在 220，说明在拼命纠一个很大的航向误差 —— 入口就不正。

### 9.4 失败模式对照

| 现象 | 原因 | 处置 |
|---|---|---|
| `el` 不是 5，车直接冲过去 | 丢线前 `\|err\|` > 0.8，被判成 CORNER/TURN90 | 进盲走前先把车摆正；或临时把 `FSM_CENTER_ERR` 放宽 |
| 一进盲走就往一边拐 | `yaw_ref` 没取对（旧固件没有"元素切换重置"） | 确认烧的是最新固件 |
| 走直线但整体偏一边 | 入口横向偏差 | 进入前让车跟线跟正；这个环没有横向反馈，改不了 |
| 600 mm 内就开始画龙 | 航向环 K 太大 + 速度环滞后 | `l -1 60` 把 `yaw_kp` 降到 0.6 |
| 走完 1830 mm 没找到线 | 落点超了 ±35 mm / 断口比量的长 | `B 2100` 再试，并复盘第 1、2 档的偏差趋势 |
| 中途停了（不到 1830） | 预算到了 | `B` 确认数值 |

### 9.5 提速的边界

横向偏移 ∝ v，所以**慢对横向有利**；但时间越长漂移越多。
按 8.2 的表，v 从 200 提到 300 会缩短时间到 5.6 s，
但同样的航向误差横向偏移会 ×1.5。**先在 200 调稳，再考虑提速。**

## 10. 「走偏」先查数据链路，别先怪精度

### 10.1 从传感器到方向盘，中间有四道关

```
HWT101 0x53 帧 → yaw_raw(int16) → ×LSB → wrap180(- zero) → 航向环 → w_ref
                     ↑              ↑        ↑                ↑
                  字节序         换算系数   零点            符号
```

任何一道错，表现出来都是"走偏"或"转不到位"，但修法完全不同。逐个查。

### 10.2 已修正：两个 LSB 都是拍脑袋的 0.01

`app_config.h` 里 `CFG_IMU_ANGLE_LSB` / `CFG_IMU_GYRO_LSB` 原来都写 `0.01`，
注释还标着 `[TODO]`（= 从没量过）。HWT101 是 WIT 标准协议：

| 帧 | 量程 | 正确 LSB | 原来写的 | 倍数误差 |
|---|---|---|---|---|
| 0x53 角度 | ±180° | 180/32768 = **0.0054932** | 0.01 | **放大 1.82 倍** |
| 0x52 角速度 | ±2000°/s | 2000/32768 = **0.061035** | 0.01 | **缩小 6.1 倍** |

后果：

1. **yaw 放大 1.82 倍** → 实际转 90°，车以为转了 164°。
   定角转弯会在转到 49° 时就"到位"收工 —— **直角弯只转一半**。
2. **角速度缩小 6.1 倍** → 角速度环的 `rate_kp×(w_ref − gyro)` 几乎为零，
   等于纯前馈。"接了陀螺仪没效果"就是这么来的。

### 10.3 已修正：航向符号在代码里是矛盾的

| 位置 | 写的公式 | 隐含假设 |
|---|---|---|
| `ctrl_core` 航向保持（原有） | `w += K*(yaw − ref)` | 右转 yaw **变小** |
| `ctrl_fsm` 定角转弯（本轮新写） | `w = K*(target − yaw)` | 右转 yaw **变大** |

**两者必有一错。** 错的那一路是正反馈，症状就是"车朝一边跑飞"。

现在统一成一个来源 `g_yaw_sgn`（`app_config.h` 的 `CFG_YAW_SGN`）：

```
w = sgn × K × (目标 − 当前)
```

右转到底 yaw 变大还是变小，取决于模块约定，**必须实测**。串口 `Y` 可以运行时翻转。

### 10.4 四个台架测试（每个 10 秒，顺序不能乱）

| # | 怎么做 | 通过标准 | 不通过说明 |
|---|---|---|---|
| 1 | 车静置，连发两次 `i`，间隔 10 s | yaw 漂移 < 1° | 零偏没标定（见 10.5） |
| 2 | `i` → 手转 90°（直角器卡住）→ `i` | Δyaw ≈ 90±3 | ≈164 → LSB 还是旧值（本次已改 0.0054932）<br>≈45 → 方向反了，改 0.01098 |
| 3 | 手把车头**【向右】**转，看 yaw 变大还是变小 | 变大 → 符号 +1<br>变小 → 符号 −1 | 与 `CFG_YAW_SGN` 不符就发 `Y` 翻转 |
| 4 | 架空，`u 90` | 转 90° 后**停住** | 一直转到超时（1.5 s）→ 正反馈，符号错 |

**第 3、4 条是一回事的静态版和动态版**，都过不去就先别上赛道。

### 10.5 零偏：上电时必须静止

HWT101 上电后会用静止状态自标定陀螺零偏。**如果上电那一刻车在动/被人碰，
零偏就是错的**，之后 yaw 会稳定地朝一个方向漂 —— 表现为"走直线但慢慢往一边偏"。

处置：断电 → 车放平、别碰 → 上电 → 等 2~3 秒再动。

### 10.6 判定「走偏」到底属于哪一类

| 现象 | 归类 | 修法 |
|---|---|---|
| 进盲走后**越走越弯**，最后甩出去 | 符号反 → 正反馈 | `Y` 翻转 |
| 走直线，但**稳定地朝一边偏**，角度不增长 | 零偏 / 入口横偏 | 静止上电；进入前跟线跟正 |
| 走直线，yaw 读数**自己慢慢涨** | 零偏 | 静止上电；必要时重标定 |
| `u 90` 转的角度**明显不到 90** | LSB 错 | 见 10.2 |
| 角度对、方向对，但**入口就偏了 20 mm** | 入口横偏 | 航向环没有横向反馈，改不了 |

### 10.7 「u 90 每次多转一点」怎么修

**2026-11-22 台架实测：右转 yaw 变小 → `CFG_YAW_SGN = -1` 正确。**
（也就是说 `ctrl_core` 原有的航向保持一直是对的，错的是我新写的定角转弯，已统一。）

剩下的是"停得不准"。三个原因，逐个对症：

| 原因 | 症状 | 本次处置 |
|---|---|---|
| **到位判据只看角度，不看角速度** | 车还在以 200 °/s 冲过目标时 `\|dh\|` 也会短暂小于容差，判据立刻成立 → 停下时已多转几度 | 新增 `CFG_TURN_STOP_DPS = 30`：角速度也要降下来才算到位 |
| **容差 2.0° 太松** | 每次都差 2°，转四次累积 8° | 收紧到 **1.2°** |
| **K=3.0 太猛** | 逼近目标时速度太高，靠 P 刹不住 | 降到 **2.0** |

> 第二条最隐蔽：**单次误差在容差内就等于"合格"，但累积会暴露。**
> 所以验转角精度不能只看一次，必须连转四次看总量 —— 这也是你发现它的方式。

#### 怎么判断是哪种原因（连转四次，每次记 `i`）

```
i           ← 记 y0
u 90  → i   ← 记 y1
u 90  → i   ← 记 y2
u 90  → i   ← 记 y3
u 90  → i   ← 记 y4
```

把 `y1-y0`、`y2-y1`… 列出来：

| 每次增量 | 结论 |
|---|---|
| 91、91、91、91（**固定偏一点**） | 到位容差问题 → 已收紧到 1.2° |
| 90、92、94、96（**递增**） | 标度误差 → LSB 不对（见 10.2） |
| 90、96、90、94（**随机大偏**） | 过冲 → 降 `CFG_TURN_KP` 或加 D 项 |
| 92、88、93、87（**正负乱跳**） | 陀螺仪噪声/振动 → 检查模块固定是否牢 |

#### 还想更准，就加 D 项（可选，要改代码）

现在角度环是纯 P。有陀螺仪不用白不用，加一项角速度阻尼能明显压掉过冲：

```c
/* ctrl_core 的 w_mode 分支里，把
 *   w_ref = clampf(g_yaw_sgn * CFG_TURN_KP * dh_t, ...);
 * 改成（Kd 约 0.3~0.6 s）： */
float yaw_rate = g_yaw_sgn * gy;            /* 与 yaw 同向的角速度 */
w_ref = clampf(g_yaw_sgn * (CFG_TURN_KP * dh_t - CFG_TURN_KD * yaw_rate),
               -CFG_W_MAX, CFG_W_MAX);
```

先在纯 P 下调到能接受，再考虑加 D —— 一次只改一处。

## 11. 2026-11-23 实测：转角慢的真正原因是纯 P 的尾段

### 11.1 数据

回滚版（`e4470d6`）跑一个直角弯，串口：

```
[el] 2   yaw=-153.8 dist=0
[el] 12  yaw=-156.0 dist=321   ← 丢线，进 EL_TURN90
[el] 13  yaw=97.7   dist=443   ← 转完，进 EL_SEEK
[seek]   dist=444 / 451 / 466
[el] 2   yaw=95.1   dist=481   ← 38 mm 后重新锁线
```

两个结论：

| 看什么 | 数值 | 判断 |
|---|---|---|
| 转角 | `wrap180(97.7-(-156.0)) = -106.3°` | 目标 105°，**差 1.3°，精度没问题** |
| 转弯里程 | `443-321 = 122 mm` @ 40 mm/s | **耗时约 2.4 s** |
| 平均角速度 | `106 / 2.4 = 43 °/s` | 电机上限 220 °/s，**慢了 5 倍** |

所以"转完停三秒"不是刹车相、不是 SEEK，是转弯本体：2.4 s + 0.22 s 刹车 + 0.2 s SEEK ≈ 2.8 s。

### 11.2 慢在哪里：尾段指令太小

纯 P（K=2.0，τ=0.5 s）的指数收尾：

| 已转 | 剩余 dh | 指令 ω | 差速 dv | 轮子实际 |
|---|---|---|---|---|
| 0° | 95° | 210 °/s | 275 mm/s | 转，但**打滑严重** |
| 90° | 5° | 10 °/s | 13 mm/s | 能转（约 20 mm/s），只是很慢 |

> **更正（2026-11-23）**：这里原来写"13 mm/s 低于死区 60，推不动"，是错的。
> `CFG_MOTOR_DEADBAND=60` 是**占空比**（0~8399），按 `CFG_SPEED_FF=9.0` 折算
> 只有 6.7 mm/s。所以尾段是"慢"，不是"不动"。这一点影响判断方向，特此修正。

前 1 s 就转完 91°，剩下 14° 磨了 1.2 s。这 1.2 s 里车还在以 40 mm/s 往前走，
把转弯弧长拉到 98 mm —— 这才是"转完看不见线"的根源（横向冲出去约 60 mm，
而 8 路视野只有 ±35 mm，只能靠 `TURN_DEG=105` 那 15° 斜插去够，很临界）。

**但更要紧的一条**：指令 220 °/s 实际只跑出 43 °/s，只剩 1/5。
这不是"给得不够"，是**轮子在空转**。所以加大差速往往适得其反——
要提速只能减少滑移（降差速、加正压力、清轮胎），不能靠加指令。

**"慢"和"冲太远"是同一个原因**，改一处两个都好。

### 11.3 改法：P 与刹车曲线取大值

`ctrl_core.c` 的 `turn_rate_cmd()`（台架 `u` 命令和 `EL_TURN90` 共用同一份）：

```
w = max( KP×|dh| , √(2×A×|dh|) )，再截到 ±CFG_W_MAX
```

- `|dh|` 大时 P 项更大 → 行为与原来完全一致，不改变撞不撞上限；
- `|dh|` 小时刹车曲线兜底，`|dh|=1.2°` 时仍有 `√(2×250×1.2) ≈ 24 °/s`，
  差速 32 mm/s（死区折算只有 6.7 mm/s，远在其上，不存在推不动的问题）。

按 A=250 估算：105° 从 2.4 s → **0.9 s**，弧长 98 mm → **37 mm**。
但 A 是"等效"值，真实角加速度受垫子摩擦、电压影响，必须实测。

### 11.4 现场调参：`T` 命令（不用重编）

```
T                    查看当前值
T 200 250 105        kp=2.00  acc=250  deg=105（kp ×100，任一项传 0 不改）
```

扫法：**固定 `kp=200`、`deg=105`，只扫 `acc`**，150 → 250 → 400。
每档跑同一个弯两次，看 `[el] 12` 与 `13` 的 yaw 差：

| 现象 | 含义 | 动作 |
|---|---|---|
| 转角仍 106° 左右、耗时 >1.5 s | acc 太小，尾段还在磨 | acc 加大 |
| 转角 108~112° | acc 太大，到点前刹不住 | acc 减小 |
| 转角 100~104° | 收得太早 | acc 略减 / deg 加大 |

一次只改一个数。改完 `T` 回车确认一次，再跑。

### 11.5 若链接报 `undefined sqrtf`

Keil AC6 默认会链 libm。万一没链上，把 `sqrtf` 换成 `sqrt`（double 版），
或在 Keil 的 `Options → Linker → Misc controls` 里加 `--library_type=libm`。

### 11.6 与"加 D 项"的关系

本文档前一节建议过加 D 项。**实测下来 D 项不是首选**：D 项抑制的是过冲，
而这里的病是尾段太慢（正好相反）。刹车曲线同时也让"到点前自动减速"，
比 D 项更直接，且不引入噪声放大（`s_de` 在 100 Hz 读数下本来就有尖峰）。

## 12. 2026-11-23 第二刀：转弯变成「真正的原地差速转」

### 12.1 现象

实车观察：转弯时**一个轮子几乎不动，另一个轮子转**，车是绕着一个轮子在兜圈，
而不是绕自身中心转。带来的后果是车身横移出去，转完 90° 车已经不在路口，
必须靠多转 15° 斜插才够得着线——所以"转角必须更大"，后续循迹也更难。

### 12.2 原因：v_cmd 固定时两轮不对称

控制律是 `左轮 = v_cmd + dv`、`右轮 = v_cmd - dv`，`v_cmd` 原来是常数 40。
`dv` 随剩余角度的平方根下降：

| 剩余 dh | 指令 ω | dv | 左轮 | 右轮 |
|---|---|---|---|---|
| 105° | 220 °/s | 420 | 460 | −380（主动反转） |
| 15° | 87 °/s | 141 | 181 | −101 |
| 1.2°（收尾） | 24.5 °/s | 21.5 | 61.5 | **+18.5 → 内轮几乎停住** |

所以"一个轮子不动"发生在**收尾段**：内轮目标被拉回到 +18 mm/s，几乎为 0。
（不是死区——`CFG_MOTOR_DEADBAND=60` 是占空比，折算仅 6.7 mm/s。）
这时只剩外轮在推，等效成"以 40 mm/s 绕 R≈54 mm 的圈"（实测弧长 99 mm / 105°）。

### 12.3 改法：v_cmd = 0

`CFG_V_TURN` 由 40 改成 **0**，两边就变成 `±dv` 的对称反转：

| 剩余 dh | dv | 左轮 | 右轮 |
|---|---|---|---|
| 105° | 420 | +420 | −420 |
| 15° | 141 | +141 | −141 |
| 1.2° | 21.5 | +21.5 | −21.5（对称，内轮真正反转） |

车心不再位移，转完 90° 车还在路口，新线仍在丢线时的位置（约 35 mm，
正好在 ±35 视野边缘），于是：

- 不再需要 105° 的 15° 斜插 → `deg` 可以降到 **92~98**；
- 转完 SEEK 的行走距离缩短，`err` 更接近 0；
- 侧移消失，出弯后循迹不用先"拉回来"。

### 12.4 风险与兜底

`v_cmd=0` 时尾段两轮目标都只有 ±21 mm/s（死区折算约 6.7 mm/s，仍在之上，但余量小），
靠死区补偿能推。极端情况（地面摩擦不均）可能卡在 dh=3~5° 不动，
此时由 `CFG_TURN_TIMEOUT_MS`（3 s）兜底进 SEEK。

所以 `v` 也做成了在线参数，卡住就在串口往上加一点：

```
T -1 -1 -1 0      纯原地差速转（默认）
T -1 -1 -1 10     两轮中心留 10 mm/s
T -1 -1 -1 20     更不容易卡，但会开始兜圈
T -1 -1 -1 -1     不改这一项
```

**不要超过 20**：`R = v/ω`，v=120 时实测横移 75 mm，直接出视野。

### 12.5 推荐的上车顺序

1. 编译后先什么都不改，跑 3 个弯。看是否出现"车原地转、车心不跑"。
2. 记 `[el] 12`→`[el] 13` 的 yaw 差（应 ≈105°）和 dist 差（应该明显小于 99 mm）。
3. 然后逐步降 `deg`：`T -1 -1 98 -1` → 95 → 92。判据是 `[el] 2` 那一行的
   `err_lv`：理想是 50~150（半路到一路半），如果变成 350（最外沿）说明降过头了。
4. 只有在"角速度上不去"时再动 `acc`；在"卡住不动"时动 `v`。两者不要同时改。

## 13. 2026-11-23 第三刀：车心还在往外溜，先分清溜在哪个阶段

### 13.1 判据：看 `dist` 差

`dist` 是 `(左轮 + 右轮)/2` 的累加（`ctrl_core.c` 第 503 行）。
`v=0` 的原地转两轮等值反向，**平均速度恒为 0**，所以：

> 真原地转 → `[el] 12` 到 `[el] 13` 的 `dist` 差 ≈ 0

这条比肉眼可靠得多，而且它能把"溜"分成两类，改法完全相反：

| dist 差 | 溜在哪 | 原因 | 改什么 |
|---|---|---|---|
| ≈ 0，但车心仍偏 | 转的过程中打滑平移 | 轮子空转、车整体滑动，里程计看不到 | 查 `v`（先 0，再试 10）、降 `acc`、查轮胎 |
| 几十毫米 | **转之前**冲出去的那段 | 丢线后还等 `arm + brake` 才转 | 调 `brake`（220 → 80 → 40） |

### 13.2 为什么"转之前"这一段必然溜

进弯时序是：丢线 → 等 120 ms（`CFG_BLIND_ARM_MS`，防抖）→ 刹车相 220 ms（`CFG_TURN_BRAKE_MS`）
→ 才开始转。这 340 ms 里车一直以 300 mm/s 前进：

```
300 × 0.12   = 36 mm   （等待确认）
刹车滑行约 25 mm
合计约 60 mm           ← 转 90° 后，这 60 mm 原封不动变成横向偏移
```

这段位移**不是控制律能消除的**，只能靠"更早开始转"。所以 `brake` 是重点旋钮。

### 13.3 `brake` 的取舍

- 大（220）：车停稳了再转，行为一致、不抖；但多溜 220 ms × 300 mm/s ≈ 66 mm。
- 小（40~80）：车还带着 100~150 mm/s 就开始给 ±420 差速，转弯相本身就在强力制动，
  总冲程反而短；代价是速度环跟不上，可能"有时好有时坏"。

甜点通常在 **60~120**。注意转弯相 `v=0` 时两轮对称，`dist` 不会涨，
所以 brake 砍掉的部分是"白赚"的横向精度。

### 13.4 这一轮加的观测

`[el]` 行末尾加了 `dt=`（该元素停留了多久）：

```
[el] 12  ... dist=339 dt=120     ← 从 el=2 到这儿用了 120 ms
[el] 13  ... dist=341 dt=980     ← 转弯本体 980 ms，dist 只涨了 2 mm ⇒ 真原地转
```

`dt` 是转弯耗时（含刹车相），`dist` 差是横向位移的证据，两个一起看就不用猜。

## 14. 2026-11-23 第四刀：内轮倍率 + 数够 7 个弯直接进盲走

### 14.1 内轮倍率 `inner`

`v=0` 之后两轮目标是严格对称的 `+dv / −dv`，但内轮是"逆向走"，
要克服整车旋转惯量 + 静摩擦 + 减速箱反向间隙，实际转速常常跟不上，
表现仍是"绕外轮转"。

所以在轮速分配处给内轮单独乘一个倍率（`ctrl_core.c` 第 7 节）：

```
dv >= 0（右转）：左轮 = v + dv          右轮 = v − dv×inner
dv <  0（左转）：左轮 = v + dv×inner    右轮 = v − dv
```

- `inner = 1.00`：与原来完全一致（对称）
- `inner = 1.25`：**当前默认**（2026-11-23 实测 `T -1 -1 -1 -1 -1 125`，
  车心外溜基本消失，直角弯明显更"原地"）
- `inner ≥ 1.30`：内轮更咬，但两轮平均速度偏负，车开始有轻微"跳"的感觉

**代价**：两轮不再对称，平均速度 = `v − dv×(inner−1)/2`，会产生一点后退分量
（车心朝车尾偏）。`inner` 越大越明显，建议不要超过 1.5。

现场：`T -1 -1 -1 -1 -1 130`（只改 inner，×100）。

### 14.2 转弯"模式"识别 → 直接进盲走

赛道进盲走区之前是**连续两个右转**，转完几乎马上就到断口。
所以真正的信号不是"第几个弯"，而是"最后连续两个弯都是右转"：

```
已转弯数 >= CFG_BLIND_MIN_TURNS (默认 5)
且  最近两次转弯方向都 == CFG_BLIND_REQ_DIR (默认 +1 = 右)
→ 下一次丢线不再转弯，直接进 EL_BLIND
```

为什么"模式"比"固定第 N 个"好：**对漏数免疫**。
灰度漏判一两个弯不影响 —— 只要最后两个是右右，照样触发。

| 判据 | 问题 |
|---|---|
| 灰度（err / slope / mabs） | 断口和直角弯区间重叠，前六轮已证明不可靠 |
| 里程 | 每个弯打滑累积约 6%（手推 7235 处，跑起来要 7692 才到） |
| 固定第 N 个 | 漏识别一个弯就永远不触发 |
| **转弯次数 + 方向序列** | 离散、不会漂，且对漏数免疫 |

实现：`enter_turn()` 里 `s_turn_cnt++` 并压入方向历史（`s_dir_h1` / `s_dir_h2`）；
EL_STRAIGHT 丢线分支**最前面**做这个判断，只触发一次（`s_blind_done`）。

现场改：`C 5 1`（至少 5 个弯、要求右右）、`C 7 0`（至少 7 个、不限方向）。

### 14.3 盲走写死航向

触发的那次盲走会把航向参考置成 **发车航向 + 180°**
（`CFG_BLIND_YAW_OFFSET`），而不是"进盲走那一刻的当前朝向"：

```
发车时（EL_START 看到线）记录 s_start_yaw
触发盲走时 → ctrl_core 把 s_yaw_ref 直接写成 wrap180(s_start_yaw + 180)
```

好处：前 7 个弯每个差 1° 的累积误差不会带进这 1.5 m。
如果实测发现盲走方向偏，改 `CFG_BLIND_YAW_OFFSET`（比如 178 / 182），或改发车摆位。

### 14.4 上车验证顺序

1. `C` 确认 `min=5 req_dir=1`，`C 0` 清零，然后正常跑一圈。
2. 每进一个直角弯会打一行 `[turn] #n/5 dir=+1 seq=[+1,+1]`：
   `#n` 是第几个，`dir` 是这次方向，`seq` 是最近两次方向。
   看到 `seq=[+1,+1]` 且 `n>=5`，下一条断线就会进盲走。
3. 第二个右转出弯后，直道尽头第一次丢线 → 应该直接进 `EL_BLIND`（`[el] 5`），
   而且**不转**（`[el] 12` 不再出现）。
4. 看盲走结束时的横向偏差，再决定要不要动 `CFG_BLIND_YAW_OFFSET`。

### 14.5 如果数错了

- **少数了一个**（某些弯没被识别）：到断口时 `cnt < 7`，不会自动进盲走，
  会退回原来的 `mabs < 0.35` 判据 —— 那条对断口是有效的，所以有兜底。
- **多数了一个**（普通弯被误判成直角弯）：会在真的直角弯处提前进盲走，车会直冲。
  这种情况把 `C` 的 min 设大 1（例如 `C 6 1`），或者确认一下方向约束对不对。

## 15. 2026-11-23 第五刀：盲走区出口直接接六边形环岛

### 15.1 为什么不能靠原来的路子

原来的链条是：盲走见线 → `EL_STRAIGHT` → 攒 150 ms 确认"线贴边" → `EL_LOOP_IN`。
两个延迟叠加起来，车会沿盲走方向**先直冲 45~90 mm**：

```
盲走速度 200 mm/s
EL_BLIND 出口要攒 FSM_RELOCK_CYCLES=2 拍（10 ms × 2）
+ EL_STRAIGHT 的 CFG_LOOP_ARM_MS 150 ms
≈ 170 ms × 200 mm/s ≈ 34 mm 直线
而且"贴边"要 4 路同时亮，实际还要再往前蹭一段
```

六边形环岛的入口切线很短，冲过去就只剩"跟着弧线跑"这一条路，
没有 `e_bias` 帮忙压内圈，车容易在第一个顶点外抛出去。

### 15.2 改法：看到线的那一拍就看形状

`EL_BLIND` 的出口条件里直接判环岛（`ctrl_fsm.c` 约 659 行）：

```c
if (line && gap_ready) {
    if (CFG_BLIND_NEXT_LOOP != 0 && trk->count >= FSM_LOOP_SIDE_CNT &&
        ((trk->left_edge == 0 && trk->right_edge < 6) ||
         (trk->right_edge == 7 && trk->left_edge > 1))) {
        /* 贴边 = 环岛入口切线 → 直接进 EL_LOOP_IN，跳过 STRAIGHT */
        s_loop_kind = (CFG_BLIND_NEXT_LOOP == 2) ? LOOP_CIRCLE : LOOP_HEX;
        s_yaw_acc   = 0.0f;      /* 绕圈角度从这里开始累计 */
        s_o.e_bias  = (err < 0) ? -FSM_LOOP_BIAS : FSM_LOOP_BIAS;
        enter(EL_LOOP_IN, ...);
    } else {
        enter(EL_STRAIGHT, ...);   /* 线居中 → 行为与原来完全一致 */
    }
}
```

判据与 `EL_STRAIGHT` 里的环岛入口**完全一致**（贴边 + ≥4 路），
所以误判概率不变：线居中的直道仍然回 STRAIGHT，不会误入环岛。

配置（`app_config.h`）：

```c
#define CFG_BLIND_NEXT_LOOP   1     /* 0=关，1=六边形(360°)，2=圆形(330°) */
```

### 15.3 六边形的绕行参数

| 项 | 值 | 说明 |
|---|---|---|
| 速度 | 180 mm/s | `CFG_V_LOOP_HEX` |
| 出口角度 | 360° | 必须整圈，少一点会从入口旁边穿出去 |
| 超时兜底 | **12000 ms** | 原来 6000 ms。按边长 300 mm、周长 1.8 m、180 mm/s 算需要约 10 s，6 s 会在绕完前把车踢出去 |
| 入口偏置 | 80 mm | `FSM_LOOP_ENTRY_MM` + `FSM_LOOP_BIAS=2.5` |

绕行中：有线就跟线（六边形的边是实线），顶点丢线时用 `e_bias` 兜住；
累计转角由 `s_yaw_acc` 每拍累加 `wrap180(yaw - yaw_last)`，进环岛时清零。

### 15.4 实测要看的日志

```
[el] 5   ...          ← 盲走
[el] 6   ...          ← LOOP_IN（应该紧跟着出现，中间不该有或只有极短的 2）
[el] 7   ...          ← LOOP_RUN
[el] 8   ...          ← LOOP_OUT
[el] 2   ...          ← 回直道
```

- 如果 `5` 后面直接是 `2`：说明盲走出口没判成环岛（线不贴边或路数不够），
  车退回普通循迹。这时看 `[el] 2` 那行的 `cnt`：≥4 且贴边才应该进环岛。
- 如果 `7` 停留 12 s 才转 `8`：是超时踢出来的，不是绕满 360° —— 说明
  `s_yaw_acc` 没攒够（可能原地打滑或在顶点外抛），先看是不是入口速度太快。

### 15.5 想放宽入口判据

`FSM_LOOP_SIDE_CNT` 现在是 4 路。如果实测"线出现时只有 2~3 路贴边"导致判不到，
可以把它降到 3，但要注意：**直道上有横向偏差时也可能瞬间贴边**，
降太多会把普通直道误判成环岛（后果是车往一侧偏 80 mm 然后再纠正，能自愈但不优雅）。

### 15.6 第一次实测："没切进去" → 加强制模式

2026-11-23 晚第一次跑，盲走结束后没进 `EL_LOOP_IN`，直接回了 `EL_STRAIGHT`。

原因：形状判据要求 **≥4 路同时贴边**。而线刚从断口边缘冒出来时，
通常只有 2~3 路压在边上（车还有横向偏差），凑不满 4 路，
判据一直不成立，于是走了普通循迹。

改法（`app_config.h`）：

```c
#define CFG_BLIND_LOOP_FORCE   1   /* 1 = 看到线就认环岛，不看形状 */
                                   /* 0 = 要 ≥4 路贴边（原判据）        */
```

强制模式下仍要求 **≥2 路**：断口里偶尔有 1 路反光被当成线，
一路不能把车诱进环岛逻辑。

顺带修了偏置方向的判断：原来用 `err` 的符号决定往哪边偏，
但线刚出现那一拍 `err` 可能接近 0，符号是随机的 —— 偏错方向车会朝外圈甩。
现在优先用"哪一路贴在边沿"（`left_edge==0` → 左，`right_edge==7` → 右），
两者都不成立才退回 `err` 符号。

### 15.7 `[el]` 行新增 `raw`

```
[el] 5  err_lv=0 mabs=0 vg=0 cnt=3 yaw=-1.2 slope=0 dist=1520 dt=7800 raw=1C fault=0004
```

`raw` 是 8 路原始字节（bit0 = 最左）。这行的 `raw=1C` = `0b00011100`
= 第 3、4、5 路亮 —— 一眼就能看出线在哪几路、是不是贴边。

盲走出口那拍如果 raw 是 `01` 或 `80`（只有最边一路），说明线刚蹭到边缘，
这就是当初判据过不了的原因。

### 15.8 第二版判据（按 20:44 的实测 raw 定）

实测数据：

```
[el] 6  err_lv=50  cnt=3 yaw=-9.6  dist=9442 dt=7300 raw=E3   ← 进环岛入口
[el] 7  err_lv=-300 cnt=2 yaw=-32.6 dist=9524 dt=450  raw=3F   ← 82 mm 后
```

`raw=E3` = `1110 0011`：左侧 bit0/1 亮、右侧 bit5/6/7 亮 ——
**环岛入口的双线分叉**（主直道的线 + 环岛切线同时可见），不是单侧贴边。

由此定下最终判据：

| 形态 | 判定 | 偏置方向 |
|---|---|---|
| 一侧贴边 + ≥3 路 | 环岛入口 | 由贴边那一侧决定 |
| 双侧都贴边（如 E3） | 环岛入口 | 用 `err` 兜底 |
| 两侧都不贴边（居中） | 回 `EL_STRAIGHT` | — |

比原来的“≥4 路同时贴边”松一档（实测只有 3 路），比“≥2 路就进”严一档。

### 15.9 入口 23° 右甩的根因：`EL_LOOP_IN` 硬偏置

数据里 `yaw -9.6 → -32.6`，82 mm 内右转 23°，把线从右侧甩到左侧
（`err +0.5 → -3.0`，`raw E3 → 3F`）。

原因：`EL_LOOP_IN` 原来**无条件**加 `±FSM_LOOP_BIAS(2.5)`，相当于硬灌一个
“误差 2.5”的方向指令，不管地上看不看得见线。

改法：入口段改成和 `EL_LOOP_RUN` 一样 —— **有线就跟线，没线才偏**：

```c
s_o.e_bias = (line) ? 0.0f : (上一拍符号 ± FSM_LOOP_BIAS);
```

入口处线通常可见（环岛切线），跟线就够了；只有六边形顶点的尖角真丢线时，
偏置才有意义。

### 15.10 串口心跳点已关闭

`CFG_CLI_HEARTBEAT = 0`。原来没收到命令时每 500 ms 打一个 `.`，
调车时会把 `[el]` / `[turn]` 日志冲散。怀疑 RX 线路不通时改回 1。

### 16.2 `[tr]` 连续跟踪日志

自动开启，不需要按任何命令：

- 进入 `EL_BLIND`（el=5）时打开
- 到 `EL_STOP`(10) / `EL_START`(1) / `EL_NONE`(0) 时关闭
- 每 100 ms 一行

```
[tr] el=5 raw=00 cnt=0 err=0   yaw=-8  w=0   dist=9400
[tr] el=6 raw=E3 cnt=3 err=0   yaw=-9  w=180 dist=9442
[tr] el=7 raw=3F cnt=2 err=-30 yaw=-32 w=-150 dist=9524
```

字段：`el` 元素、`raw` 8 路原始字节、`cnt` 压线路数、`err` 加权误差、
`yaw` 航向、`w` 期望角速度、`dist` 里程。

**这是判断"环岛到底发生了什么"最直接的证据**：`raw` 的形态（单侧全亮 / 双侧分叉）、
`err` 的符号和大小、`w` 的方向，三样一对就知道它是跟线、偏置还是乱走。

### 16.3 终点全黑停车

```c
#define CFG_FINISH_MS   40u     /* 0 = 关闭 */
```

逻辑：

1. 走出盲走时把 `s_finish_armed` 置 1（因为后面已经没有直角弯了）
2. `EL_STRAIGHT` 里，**在"全黑 → 路口"判断之前**先查终点：
   全黑（`trk->junction`，即 8 路全压）持续 40 ms → `EL_STOP`

为什么不会误判：

- 赛道的"全黑"只有两处：发车/终点那条横跨赛道的黑带、以及路口；
- 而"丢线"是 **0 路亮**，跟全黑正好相反，不会混；
- 盲走之后已经没有直角弯，所以武装后第一次全黑必然是终点。

40 ms 比路口的 15 ms（`FSM_JUNCTION_MS`）长，是为了避开单帧噪声。
如果实测发现"还没到终点就停了"，说明 40 ms 太短或途中有一段真全黑，把它加到 80。

## 17. 2026-11-24 开环差速转弯（写死差速 + 定时）

### 17.1 为什么加这条路

闭环的问题在打滑严重时暴露得很彻底：

```
指令 220 °/s → 实际 42 °/s（差 5 倍）
P 项长期饱和（w 被截在 W_MAX），刹车曲线也失去意义
```

也就是说闭环**在追一个追不到的目标**，每次停在哪个角度取决于当次打滑，
行为不可预测。开环反过来：给固定差速，实际角速度是稳的，
“转多少度 = 角速度 × 时间”，标定一次就够。

### 17.2 实现

`EL_TURN90` 里多了一条分支（`CFG_TURN_MODE=1` 时走）：

```c
s_o.w_mode  = 2u;                        /* 2 = 开环差速 */
s_o.dv_open = s_turn_dir * g_turn_open_dv;
set_speed_target(0.0f);                  /* 两轮 ±dv，纯原地转 */
if (经过时间 >= g_turn_open_ms) → EL_SEEK
```

`ctrl_core` 的第 6 步直接取 `dv_open`，**不掺陀螺仪反馈**：

```c
if (fo->w_mode == 2u) dv = clampf(fo->dv_open, ±CFG_DV_MAX);
else                  dv = RATE_FF*w + rate_kp*(w - gyro);
```

内轮倍率（`inner=1.25`）在开环下同样生效。
转向符号改用 `dv_open` 的符号判断（开环时 `w_ref` 恒为 0，用它会把左右转判反）。

### 17.3 命令与标定

```
O                    → turn mode=0 dv=260 ms=1000
O 1 260 1000         开环，差速 260 mm/s，持续 1000 ms
O 0                  回闭环
O -1 -1 1500         只改时间
```

标定（差速恒定 ⇒ **角度 ∝ 时间**）：

| 步骤 | 动作 |
|---|---|
| 1 | `O 1 260 1000`，跑一个弯 |
| 2 | 看 `[el] 12` → `[el] 13` 的 yaw 差，记作 θ₁ |
| 3 | 需要 90° 的时间 = `1000 × 90 / θ₁`，用 `O -1 -1 <ms>` 写入 |
| 4 | 再跑两三次核对，落点差 ≤3° 就可以定下来 |

`dv` 决定“转多快”和“打滑程度”。太大只会让轮子空转、角速度不再上升，
所以是“找到刚好不空转的那个值”，不是越大越好。建议 200 / 260 / 320 三档扫。

### 17.4 开环 vs 闭环，怎么选

| | 开环（mode=1） | 闭环（mode=0） |
|---|---|---|
| 一致性 | 地面/电池不变时**每次一样** | 每次随打滑浮动 |
| 抗扰动 | 差（电池掉了、换地面就偏） | 好（自动收敛） |
| 调试成本 | 要标定一次时间 | 参数多但自适应 |
| 风险 | 转不够/转过头都没有兜底 | 有 `CFG_TURN_DEG` 上界和超时 |

**建议**：先用开环跑 3 次同一处弯，看 yaw 差是否稳定在 ±3° 内。
- 稳定 → 用开环，简单可预测；
- 不稳定（比如 88/95/102 乱跳）→ 说明打滑本身不可重复，开环没用，回闭环。

验证数据就在 `[el] 12` 与 `[el] 13` 两行的 yaw 里，不用额外工具。

## 18. 2026-11-24 外轮系数：把"车心"收回路口

### 18.1 只有 inner 不够

之前只有内轮倍率 `inner`，外轮恒为 1.0 倍 `dv`。但几何上是这样的（v_cmd=0 时）：

| 两轮关系 | 车心 |
|---|---|
| 等值反向（outer=1.00, inner=1.00） | 不动，绕自身中心转 |
| outer < inner（外慢内快） | vc<0，**朝外轮一侧偏**（右转时朝左） |
| outer > inner（外快内慢） | vc>0，**朝内轮一侧偏**（右转时朝右） |

`inner=1.25` 单独用时，外轮还是 1.0 倍，所以车心是"略微朝内"，
但幅度只由 inner 一个旋钮控制，**外轮没有独立调节权**。

用户的实际观察是：转完之后车离黑线太远，得靠巡线拉回来。
这说明车心往外偏了 —— 需要 `outer < 1` 和 `inner > 1` 同时作用。

### 18.2 新增 `outer`

```c
左轮（外） = +dv × outer
右轮（内） = -dv × inner
```

- `CFG_TURN_OUTER = 1.00`（默认，与原行为一致）
- 现场：`T` 命令第 7 个参数（×100）

```
T                           → ... inner=1.25 outer=1.00
T -1 -1 -1 -1 -1 140 90     → inner=1.40  outer=0.90（车心往内收）
T -1 -1 -1 -1 -1 0 0        → 恢复对称（两轮都 1.0 倍）
```

### 18.3 调法（一次 0.05）

看到"转完离黑线远、要巡线拉回"时：

1. `outer` 从 1.00 降到 0.95，`inner` 从 1.25 升到 1.30，跑同一个弯
2. 看 `[el] 2` 那行的 `err_lv`：
   - 还是 300+（贴最边）→ 继续收
   - 变成 50~150（半路）→ 到了
   - 变成 -300 或另一侧贴边 → 收过头了，往回收一档
3. 每次只动 0.05，两个旋钮同步反向动（outer−0.05 / inner+0.05）

**不要靠改 `deg` 去补横向偏差**：deg 改的是"转多少度"，
车心偏的是"位置"，两件事。用 deg 补位置会出现"角度对了但车是斜着走的"。

## 19. 2026-11-24 修正：环岛触发必须是"三重同意"

### 19.1 之前的漏洞

第 15 节那一版把环岛判据直接塞进 `EL_BLIND` 的出口，只看了**线的形状**：

```c
if (line && (一侧贴边 + ≥3 路)) → EL_LOOP_IN
```

问题是 `EL_BLIND` 有四条进入路径：

| 进入方式 | 有没有"数够弯"这层约束 |
|---|---|
| 数够 N 个弯 + 最后两次同向（`s_blind_lock=1`） | 有 |
| 里程窗锁进来（`G` 命令） | **没有** |
| `Z` 强制盲走 | **没有** |
| 灰度误判 | **没有** |

也就是说：只要盲走是被后三种方式进来的，车在半程任何一处贴边都可能被当成环岛入口。
**光看线形状不够，必须先过"计数"和"里程"两关。**

### 19.2 现在改成三重同意

```c
if (CFG_BLIND_NEXT_LOOP != 0 &&
    s_blind_lock != 0u &&                       /* ① 转弯次数 */
    (dist_mm - s_d_run0) >= CFG_LOOP_RUN_MIN_MM &&  /* ② 里程 */
    trk && (一侧贴边 + ≥3 路 或 双侧贴边)) {     /* ③ 形状 */
    → EL_LOOP_IN
}
```

**① 转弯次数** 用 `s_blind_lock`，而不是重新数 `s_turn_cnt`：

这个标志只有"数够 `CFG_BLIND_MIN_TURNS` 个弯、且最近两次方向都等于 `CFG_BLIND_REQ_DIR`"
那次盲走才会置 1，且只在**那一次**盲走期间有效（退出盲走时清零）。
所以它本身就等价于"转弯次数 + 方向序列"这一整组条件，比单独读 `s_turn_cnt` 更准确
（`s_turn_cnt` 只增不减，进了盲走之后还会被下一次转弯累加）。

**② 里程** `CFG_LOOP_RUN_MIN_MM`（默认 8000 mm，相对发车原点）：

实测入口在 `dist≈9442`（`[el] 6` 那行）。给 8000 当下限，低于这个一律不认。
换发车位置要重新标 —— 跑一圈看 `[el] 6` 的 dist，取它减 1400 左右。

**③ 形状** 保持第 15 节定的规则（一侧贴边 ≥3 路 / 双侧贴边）。

### 19.3 为什么圆形环岛不加这条

赛道右上还有一个圆形环岛，它在赛程**前半段**（第 1~2 个弯附近），
没有"数够 5 个弯"这个前提。所以 `EL_STRAIGHT` 里那个原有判据
（`count >= FSM_LOOP_SIDE_CNT` + 贴边 + 持续 150 ms）保持不变。

**两个环岛用两套判据是故意的**，不是漏改：
- 圆形环岛 → 早，靠形状 + 持续时间
- 六边形环岛 → 晚，靠次数 + 里程 + 形状

### 19.4 调试时怎么确认

`[tr]` 日志里能直接看到这三条：

```
[tr] el=5 raw=00 cnt=0 ... dist=9300    ← 盲走中，里程还没到 8000？看 dist 列
[tr] el=5 raw=C0 cnt=2 ... dist=9450    ← 贴边了，但 el 还是 5 → 说明没进环岛
                                           检查：dist 够吗？s_blind_lock 是 1 吗？
```

如果 `dist` 明显过了 8000、线也贴边，却一直在 `el=5`／跳到 `el=2`，
那就是 `s_blind_lock` 没置 1 —— 回去看 `[turn]` 那几行，最后两次方向是不是都是 `+1`。
