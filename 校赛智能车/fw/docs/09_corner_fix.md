# 09 弯道冲出去：根因定位与修法

> 交接时状态："直线能跑，弯道冲出去，需要调。"
> 本文给的不是"试试这组参数"，是**算出来的因果**。
> **2026-11-21 22:56 现场实测已确认参数**，见第 0 节，结论与初版推演不同 —— 以本文为准。

## 0. 现场实测（先看这个）

```
c
[cli] steer kp=70.0 kd=6.0  vs=300 vc=250
```

- **kp = 70.0**：这是 `app_config.h` 的默认值，转弯能力充足（上限 220 °/s，
  250 mm/s 下最小转弯半径 65 mm）。**所以"转不过来"不成立，初版把 kp 当主因是错的。**
- **kd = 6.0**：这是主因。下一节算给你看。
- vs=300 / vc=250：弯道只比直道慢 17%，弯里减速基本没发生 —— 这是次要问题。

| # | 缺陷 | 位置 | 性质 | 优先级 |
|---|---|---|---|---|
| ① | **kd=6.0 把 8 路量化台阶放大成方向抖动** | `ctrl_core.c` 第 450~456 行 | 改参数即可，**不用编译** | **最高** |
| ② | 丢线瞬间误差强制归零 → 转向指令消失 | `ctrl_core.c` 第 443 行 | 代码错，**要编译** | 高 |
| ③ | 文档教 `c 60`，实际 kp 只有默认值的 1/11.7 | 08_tuning / 先看这个 | 文档陷阱（不是当前故障） | 中 |
| ④ | D 项用 5 ms 求导，但循迹是 100 Hz 读的 | `ctrl_core.c` 第 451 行 | 代码，可一起修 | 低 |

## 1. 主因①：kd=6.0 在离散误差上打满方向

### 误差是台阶，不是连续量

8 路探头，权重 -3.5 … +3.5，相邻差 1.0；两路中点再补 0.5。
所以 `err` 只会以 **0.5 的整数倍**跳变（一次换位通常 `Δe = 1.0`）。

误差还经过 20 Hz 一阶低通（`CFG_ERR_LPF_HZ`），200 Hz 采样下每拍走 **38.6%**：

| 拍 | `e_f` 变化 | `de = Δe_f / 0.005` | `kd=6` 时 D 项 |
|---|---|---|---|
| 1 | 0.386 | 77 pitch/s | **463 °/s** → 封顶 220 |
| 2 | 0.237 | 47 pitch/s | **284 °/s** → 封顶 220 |
| 3 | 0.146 | 29 pitch/s | 175 °/s |
| 4 | 0.090 | 18 pitch/s | 108 °/s |

弯道里真正需要的角速度是多少？250 mm/s 过 R=250 mm 的弯：

```
ω = v / R = 250 / 250 = 1 rad/s = 57 °/s
```

**所以 D 项一次换位就打出 463 °/s，是 P 项需求量的 8 倍，并且封顶 2~3 拍（10~15 ms）。**
它反映的不是"误差在变大"，是量化噪声。

### 为什么"直道能跑、弯道冲出去"

| 场景 | `err` 行为 | `de` | D 项 | 结果 |
|---|---|---|---|---|
| 直道 | 基本不变 | ≈ 0 | 静音 | 平稳 ✅ |
| 弯道 | 每 10 ms 跳一个台阶 | 频繁 77 pitch/s | 反复打满 | 猛顿 / 甩 / 冲线 ❌ |

这条因果链能完整解释交接描述的现象，不需要任何额外假设。

### 上车验证（不用编译，两分钟）

```
c 700 0 250 200     ← kp 不变(70)，kd 归零，速度顺手降到 250/200
a                   ← 跑两圈
```

| 现象 | 结论 |
|---|---|
| 弯里明显变顺、不甩 | ✅ 确认是 D 项。进下一节找 kd 的合适值 |
| 弯里切外道但平滑 | kp/速度问题，不是 D |
| 还是冲出去，且 `d` 的 `e` 掉回 0 | 是缺陷②，跳到第 2 节 |

反向验证（可选，但很有说服力）：

```
c 700 50 250 200    ← kd 回到 5.0，应当明显变差
```

### kd 的可用范围

要让 D 噪声不超过 30 °/s（约 P 项的一半）：

```
kd <= 30 / 77 ≈ 0.39     →  命令写 c ? 4 以内
```

实际取 **0 ~ 1.5（CLI `0`~`15`）**。旧文档写的"kd 加到 60~100"是错的，
那等于把量化噪声放大 10 倍。

> 想真正用上 D（前瞻），必须先在代码里把微分做对：对 `de` 加 5~8 Hz 低通，
> 或者用 20~30 ms 的差分窗口，而不是现在的 5 ms。见第 4 节。

## 2. 次因②：丢线 → 误差归零 → 转向指令消失

### 代码事实

`bsp_track.c`：8 路全白时 `cnt==0` → `f->valid=0`、`f->err=0.0f`。

`ctrl_core.c` 第 443 行：

```c
e = (line_ok ? s_feat.err : 0.0f) + fo->e_bias;
```

线一旦跑出 8 路视野（约 ±35 mm），`e` 立刻变 0 → `w_ref = 0` → 车头回正 → **直冲**。
而 `fo->e_bias` 在 `EL_CORNER` 里是 0（只在 STRAIGHT / LOOP 里赋值），
所以状态机虽然还停在 `EL_CORNER`（`v` 显示 `el=3`），转向已经放弃了。

叠加低通：`e_f` 会用 4~5 拍从 3.5 慢慢放到 0，车表现为"一边收油一边直冲出去"。

### 修法（需要 Keil 编译）

**① 静态变量区**（`static float s_e_prev;` 附近）加：

```c
/* 短时失线保持：线跑出视野的一刹那不要立刻放弃转向。 */
static float    s_e_hold;        /* 最后一次有效误差 */
static uint32_t s_e_hold_ms;     /* 它出现的时刻 */
```

**② `ctrl_step()` 第 443 行这一句：**

```c
e = (line_ok ? s_feat.err : 0.0f) + fo->e_bias;
```

替换为：

```c
/* 看到线：刷新保持值；短暂失线：沿用上次误差继续打方向；
 * 长时间失线：放弃，交给丢线保护。 */
if (line_ok) {
    s_e_hold    = s_feat.err;
    s_e_hold_ms = now;
}
{
    float e_raw;
    if (line_ok) {
        e_raw = s_feat.err;
    } else if (fo->kp_scale > 0.0f &&
               (uint32_t)(now - s_e_hold_ms) < CFG_E_HOLD_MS) {
        e_raw = s_e_hold;
    } else {
        e_raw = 0.0f;
    }
    e = e_raw + fo->e_bias;
}
```

**③ `app_config.h` 转向段加参数：**

```c
/* 短时失线保持时长：这段时间沿用最后一次线位置继续打方向。
 * 250 mm/s 下 150 ms ≈ 37 mm，够 8 路探头（约 70 mm 跨度）重新捕获线。
 * 别超过 250，否则真丢线时车会继续瞎转。 */
#define CFG_E_HOLD_MS   150u
```

### 为什么安全

| 状态 | `kp_scale` | 影响 |
|---|---|---|
| `EL_STRAIGHT` | 1.0 | 失线 30 ms 后进 BLIND/CORNER，保持只为过渡 |
| `EL_CORNER` | 1.2 | ✅ 正是要救的场景 |
| `EL_SCURVE` | 0.75 | ✅ 有益 |
| `EL_BLIND` | **0.0** | 位置项本来就屏蔽，无影响 |
| `EL_CROSS` | **0.0** | 同上 |
| `EL_STOP` | 0.0 | 无影响 |

真丢线时：150 ms 后 `e` 归零，300 ms 后 `CFG_TRACK_LOST_STOP_MS` 触发
`FAULT_LINE_LOST` 停车。保护链完整。

## 3. 缺陷③：文档的 kp 缩放陷阱（会坑下一个接手的人）

头文件 `CFG_STEER_KP = 70.0`，而串口命令把它除以 10：

```c
ctrl_set_steer((float)a / 10.0f, (float)b / 10.0f);   /* c 60 → kp=6.0 */
```

旧文档教的是 `c 60 60`，只有默认值的 1/11.7，上限 21 °/s、最小转弯半径 682 mm。
**任何人照抄都会得到一台过不了弯的车**，然后再也调不出来（因为 kd 也被同时放大到 6）。

现在 08_tuning.md 已改为：**kp 写百位、kd 写个位**。

| 想设 | 命令 |
|---|---|
| kp=70, kd=0 | `c 700 0` |
| kp=70, kd=1.0 | `c 700 10` |
| kp=50, kd=0.5 | `c 500 5` |

`c` 不带参数时回显的 `kp=70.0 kd=6.0` 就是真实增益，`vs/vc` 是速度（mm/s）。

## 4. 缺陷④：D 项的采样间隔算错（想用 D 必须先修这个）

`ctrl_core.c` 第 451 行：

```c
float de = (e_f - s_e_prev) / dt;      /* dt = 5 ms */
```

但循迹是 **100 Hz** 读的（`s_trk_div` 每 2 拍读一次，第 323 行）。
每 2 拍只有 1 拍有新数据：有数据的拍 `de` 是真实变化率的 **2 倍**，另一拍 ≈ 0。
D 项因此变成 100 Hz 方波。

建议改成"有数据才求导 + 对 de 低通"：

```c
static float s_de_filt;
static float s_d_term;

if (trk_fresh) {                       /* 本拍读到新数据 */
    float de = (e_f - s_e_prev) / (dt * (float)CFG_FSM_DIVIDER);
    s_e_prev = e_f;
    /* 一阶低通 6 Hz：把量化台阶和 100 Hz 方波一起压掉 */
    s_de_filt += 0.159f * (de - s_de_filt);      /* alpha ≈ 2π*6/200 */
    s_d_term = line_ok ? s_p.steer_kd * s_de_filt : 0.0f;
}
w_ref = fo->kp_scale * (s_p.steer_kp * e_f + s_d_term);
```

修完之后 kd 才可能用到大一点的值（`c 700 20`~`c 700 40`）。
**在此之前 kd 就该待在 0~15。** 不要为了"弯道更贴"去加 kd，
先把①的抖动消掉，弯道自然就顺了。

## 7. 「一加速就冲出去」怎么拆

低速能跑、一提速就飞，说明系统**余量很小**。先按下面四条排掉几何和设定问题，再谈改代码。

### 7.1 先排掉几何天花板（算术，不可调）

转向角速度被 `CFG_W_MAX = 220 °/s` 硬限死，所以速度越快，能过的最小半径越大：

```
R_min = v / (220 × π/180) = v / 3.84
```

| 直道速度 | 能过的最小弯半径 |
|---|---|
| 200 mm/s | 52 mm |
| 300 mm/s | 78 mm |
| 400 mm/s | 104 mm |
| 500 mm/s | 130 mm |
| 600 mm/s | 156 mm |
| 800 mm/s | 208 mm |

**如果赛道最急的弯比表里的值还小，那不是 bug，是速度超了。**
量法：沿弯道中线量出 90° 的弧长 L，半径 `R = 2L/π`。

> 附带发现：执行机构其实还有余量。差速上限 `CFG_DV_MAX = 420`，对应物理角速度
> `2×420/150 = 5.6 rad/s = 320 °/s`。**220 °/s 这个钳位比硬件保守了 45%。**
> 高速阶段可以考虑把 `CFG_W_MAX` 和 `CFG_STEER_KP_MAX` 一起提到 260~300（要编译）。

### 7.2 弯道减速几乎没发生

现在 `vs=300 / vc=250`，只差 17%。而 FSM 要 `|err| > 2.0` 持续 **50 ms** 才切弯道速度
（`FSM_CORNER_HOLD_MS`），400 mm/s 下这 50 ms 已经走了 20 mm —— **降速发生在入弯之后**。

建议 vc 取 vs 的 **60~70%**：

```
c 700 0 300 180
```

### 7.3 陀螺仪符号从来没验证过（`rate_kp` 默认是开着的）

`CFG_RATE_KP = 0.35`，`CFG_GYRO_INVERT = 0`，而 08 文档 6.5 节写明"符号未验证"。
符号反了不会自激（环路增益 `0.35 × 0.764 = 0.27 < 1`），但会：

- 把实际转向放大 `1/(1-0.27) ≈ 1.36` 倍
- **吃掉阻尼**，放大倍数还随角速度增大

所以症状正好是"**慢的时候没事，一快就炸**"。30 秒验证：

```
j                  ← 架空，手把车头往【右】转
```

第二列（陀螺仪，右转为正）应变**正**。变负 → `CFG_GYRO_INVERT` 改 1，重编。

### 7.4 延迟清单（合计约 90 ms，这就是余量小的根源）

| 环节 | 延迟 | 位置 |
|---|---|---|
| 循迹采样（每 2 拍读一次） | 10 ms + 1.6 ms 读取 | `ctrl_core.c:323` |
| 误差一阶低通 20 Hz | ≈ 8 ms | `CFG_ERR_LPF_HZ` |
| 占空比斜坡 300/5ms | 满舵差速需 **43 ms** | `CFG_DUTY_SLEW` |
| 测速窗口 4×5 ms + 30 Hz 低通 | ≈ 30 ms | `SPEED_WIN_N` |

600 mm/s 下 90 ms = **54 mm**，超过 8 路探头 70 mm 跨度的大半。这就是"低速能凑合、
一提速就没救"的物理原因。

**最便宜的一刀**：循迹从 100 Hz 提到 200 Hz —— 把 `s_trk_div` 的 `/2` 去掉即可
（I2C 一次 1.6 ms，占用 32% CPU，可接受），采样延迟直接砍半。
剩下的斜坡和测速窗口是安全装置/噪声抑制，不建议动。

## 8. 「突然加速」：`c` 命令管不到的三处速度

### 8.1 事实

`c` 命令只走 `fsm_set_speeds()`，它只改两个变量：`s_v_straight`、`s_v_corner`。
**另外三个元素的速度是编译期宏，`c` 改不到**：

> ✅ **2026-11-21 23:45 已按方案 A 改掉（见 8.5）。下表是改动前的原始值，留作记录。**
> 现在这四个宏是 200 / 200 / 180 / 200，误触发只会「不变速」。

| 状态 `el` | 元素 | 速度来源 | 值 |
|---|---|---|---|
| 4 | `EL_SCURVE` | `CFG_V_SCURVE` | **600 mm/s** |
| 5 | `EL_BLIND` | `CFG_V_BLIND` | **750 mm/s** |
| 6/7 | `EL_LOOP_IN/RUN` | `CFG_V_LOOP_CIRCLE / _HEX` | **500 / 400 mm/s** |
| 2 / 3 | 直道 / 弯道 | `s_v_straight / s_v_corner` | 你设的（`c` 可改） |

所以你把直道弯道都设成 100，只要状态机切进 S 弯或盲走，目标速度立刻变成
**600 / 750** —— 速度指令按 1200 mm/s² 爬升，**0.4~0.5 s 就冲上去了**。

### 8.2 这两个状态的触发条件有多松

| 状态 | 触发条件（`ctrl_fsm.c`） | 误触发有多容易 |
|---|---|---|
| `EL_SCURVE` | 150 ms 内 `err` 符号翻转 **≥2 次**（每次 \|err\|>0.3） | 车在线上正常摆两下就满足 → **kHz 级噪声也算** |
| `EL_BLIND` | 丢线 30 ms，且丢线前 \|err\|<0.8 | 胶带接缝、反光、传感器高度不对，任何一个瞬间丢线就中 |
| `EL_LOOP_IN` | 一侧连压 ≥4 路且贴边（`left_edge==0 && right_edge<6`） | **车偏到一边、压住 4 个探头就中** —— 正是"冲出去之前"的车身姿态 |

而且这两个状态进来之后不只是加速：

- `EL_SCURVE`：`kp_scale = 0.75`（转向被削弱 25%）+ 速度 600
- `EL_BLIND` / `EL_CROSS`：`kp_scale = 0`（**位置环完全断开**，只剩航向保持）+ 速度 750

**"突然加速 + 同时不怎么拐弯"—— 这就是冲出去的组合拳。**

### 8.3 为什么"调慢之后反而更容易察觉"

跳变是**绝对值**，不是倍数：不管你把直道设成 300 还是 100，误触发后都是 600/750。

- 直道 300 → 跳到 600，2 倍，还能忍
- 直道 100 → 跳到 600，**6 倍**，看着就是"弹射"

所以这个 bug 一直都在，你把速度调下来之后它才变得刺眼。

### 8.4 怎么抓（不用编译）

```
o                  ← 50 ms 一行：[v_ref_l] speed_l speed_r duty_l duty_r
a
```

第一列是**左轮目标速度**。正常跑在你的设定值附近（±dv）；如果**突然跳到 600~750**，
就是状态机进了 S 弯 / 盲走。这时立刻发 `v` 看 `el=`：

| `el` | 结论 |
|---|---|
| 4 | S 弯误触发 |
| 5 | 盲走误触发 |
| 6 / 7 | 环岛误触发 |

### 8.5 怎么修（要编译，二选一）

**方案 A（已采用，2026-11-21 23:45）**：元素还没验收，就别让它跑快。
`app_config.h` 里这四个值已改成：

```c
#define CFG_V_SCURVE        200.0f   /* 原 600：元素未上车，先压住 */
#define CFG_V_BLIND         200.0f   /* 原 750 */
#define CFG_V_LOOP_CIRCLE   200.0f   /* 原 500 */
#define CFG_V_LOOP_HEX      180.0f   /* 原 400 */
```

> ⚠️ **烧录/复位后速度会回到宏里的默认值**（`CFG_V_STRAIGHT 300 / CFG_V_CORNER 250`），
> 之前用 `c` 设的 150/100 不会保留（那些只在 RAM 里）。所以每次上电要重新发一次 `c`。
> 嫌麻烦就把 `CFG_V_STRAIGHT / CFG_V_CORNER` 的默认值也改成你常用的那组。

误触发只会"不变速"，不会弹射。等元素真上车标定完再逐个放开。
**代价是零** —— 这几个状态现在本来就没验收过。

**方案 B（更彻底）**：加一个总开关，元素未验收前只允许 `STRAIGHT` / `CORNER`：

```c
#define CFG_ELEM_ENABLE  0   /* 0 = 只跑直道和弯道，S弯/盲走/环岛/十字全部禁用 */
```

在 `ctrl_fsm.c` 的 `EL_STRAIGHT` 分支里，把 3) 环岛、4) S 弯、2) 盲走 三个转移
都用 `#if CFG_ELEM_ENABLE` 包起来。这样连"误判"的机会都没有。

### 8.6 顺带：S 弯的判据本身就该改

即使以后要开 S 弯，"150 ms 内翻 2 次"也太松了。建议至少三条同时满足：

- 翻转次数 ≥ 4（`FSM_OSC_FLIPS` 2 → 4）
- 每次翻转的幅度 ≥ 1.0（现在只要 >0.3）
- 进入前连续 `|err| < 0.8` 的时间 ≥ 200 ms（确认是先走直了才进 S）

否则它就是在把"循迹噪声"当成"S 弯"。
